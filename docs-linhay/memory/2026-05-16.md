## Hybrid transport smoke closed

- 最新需求从“WebSocket + HTTP hybrid architecture with smoke test”推进到可复跑闭环。
- 修复 SwiftPM 在 macOS 上构建 `TritonKit` 时因 UIKit 无条件编译失败的问题，UIKit 相关采集能力改为 `canImport(UIKit)` 条件编译。
- CLI 默认端口对齐项目治理规则为 `19421`，Demo 默认端口与 WebSocket route 文案同步为 `ws://127.0.0.1:19421/`。
- `TritonKit` 收到首条 WebSocket 消息后会进入 `connected` 状态。
- hierarchy 读取与控制采用 `iOS App -> WebSocket -> CLI/HTTP JSON -> AI agent`：WebSocket 保持 iOS 与 CLI 双向控制，AI 不需要 Web 端。
- 新增 `/status`、`/command`、`/hierarchy/latest`，AI agent 可读取连接状态、下发 `ping/appInfo/hierarchy` 并获取最新 hierarchy JSON。
- 验证通过：`swift test`、`swift build --product triton`、CLI HTTP smoke、iOS Simulator build/run、AI CLI/HTTP command smoke；测试覆盖 `TKMessage`、`TKDisplayItem.flatItems` 与 macOS 非 UIKit fallback。

## Subagent 体验与 AI 诊断

- 按用户要求开启 subagent 体验当前 CLI；结论是命令面已接近首期 AI 可控 CLI，最大摩擦是无服务时 `--format json` 仍输出 Foundation 长错误，第二优先是缺少一条 capabilities/doctor 探测命令。
- 已新增 `triton doctor` 与 `triton capabilities`，并新增共享 `TKCLIErrorResponse`、`TKCapabilitiesResponse`、`TKRuntimeCapability`。`doctor/capabilities --format json` 在 server 不可达时输出 `server_unavailable` 与启动 hint，并以 0 退出供 AI 读取。
- `status/list --format json` 在 server 不可达时输出统一 `{ok:false,error:{code,message,endpoint,hint}}` envelope，并以 1 退出；连接态 `capabilities` 验证 `runtime=embedded`、`tap=true`、`press=false`。

## Recovery plan loop

- 第四轮 subagent 体验指出 AI 能读 schema 后仍缺少“失败后下一步怎么做”的结构化动作，且 `status` 未进入 schema。
- 已新增 `TKCLINextAction` 并扩展 `TKCLIErrorDetail.nextAction`；无 server 时 `status --format json`、`doctor/capabilities` 与 `plan` 都能给出 `serve --host 127.0.0.1 --port 19421` 的机器可执行恢复动作。
- 已新增 `triton plan` 与 `status/plan` schema。`plan` 不依赖 server，server 不可达时输出 `nextStep=start-server`，连接态输出 `nextStep=observe` 与 `geometry/ax/hit/input/screenshot/export archive` 推荐序列。
- 验证通过：`swift test`、`swift build --product triton`、`triton plan --format json/text`、`triton schema --command status --format json`、`triton schema --command plan --format json`、`triton status --format json` 无服务失败 envelope、临时 server 连接态 `plan`；结束后确认 `19421` 无监听进程。
