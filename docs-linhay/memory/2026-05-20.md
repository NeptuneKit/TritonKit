## Issue #2 Homebrew pre-release fallback

- 线上确认：`NeptuneKit/TritonKit` 暂无 GitHub Release，`NeptuneKit/homebrew-tap` 仓库暂不存在。
- 决策：首个 `v*` release 与 tap 仓库可用前，README 与项目级 skill 的 CLI 接入指南必须先给 `swift build -c release --product triton` 本地 release CLI fallback，Homebrew 只作为发布后路径。

## Issue #1 target cache state

- 根因：server 的 `TargetState` 同时保存当前连接 identity 与 latest hierarchy cache；新 WebSocket 连接建立时未清空当前 identity，可能在新 App 的 app info / hierarchy 返回前让 `/targets` 暴露上一轮 App metadata。
- 修复方向：新连接和断开时清空当前 identity、active hierarchy 标记和 pending responses，但保留 latest hierarchy cache；WebSocket 断开按 connection generation 清理，避免旧连接迟到退出覆盖新连接；`status` / `doctor` / `list` JSON 增加 `activeHierarchyAvailable`、`hierarchyCacheState`、`targetConnectionState` / `identityState` 等字段，明确 active target 与 stale cache 的区别。

## Issue #4 visible UIKit text in AX

- 根因：`TritonKitRequestHandler.collectAXLeafNodes` 以安全叶子节点为主，`UIScrollView` / `UICollectionView` 容器导出时不携带子节点；同时 AX 构建深度和节点预算偏保守，复杂 collection-view 页面容易在深层 cell 文本前停止。
- 修复：AX 构建改为 scroll 容器嵌套子节点，默认 `maxDepth` 提升到 32、`maxNodes` 提升到 800；空 `UIImageView` / 空 label 不再进入 AX 输出；文本兜底覆盖 `UILabel.attributedText`、`UIButton.currentAttributedTitle`、`UITextField.placeholder` 等公开 UIKit 属性。
- 验证：新增 iOS-only UIKit 回归测试描述 collection view 深层 label；macOS `swift test` 通过 32 个可执行测试，`xcodebuild build -scheme TritonKit -destination 'platform=iOS Simulator,name=iPhone 17'` 通过。iOS package test 目前被 `triton` 可执行目标依赖的 iOS 15/17 minimum deployment 阻断，后续可独立整理测试 scheme。

## Issue #3 exact text input

- 决策：精确文本输入先使用 embedded runtime 内公开 UIKit `UIKeyInput` API，不依赖 Simulator pasteboard、AppleScript 或 host-side HID；`paste` 语义是 exact insertion，而不是系统剪贴板粘贴。
- 新增 `TKInputType.paste` / `clear`、`triton paste <text>`、`triton clear`，均支持当前 first responder、`--oid` 和 `--x/--y` 坐标聚焦路径；`type --exact` 保留为显式精确输入口径。
- 敏感字段通过 `--secure` 标记，结果只回显 `secure/redacted/insertedLength`，不在 `TKInputResult` 中回显原始文本。

## Issue #5 wait/assertion commands

- 新增 `triton wait`，支持 `--text`、`--gone`、`--exists --role`、`--idle`、`--hierarchy-change --since latest` 与安全 `--predicate`。
- JSON 默认返回 `TKWaitResult`，包含 `condition/query/predicate/elapsedMs/pollCount/timedOut/targetConnectionState/hierarchyCacheState/lastObservedTextSample/match`；超时输出 `ok=false,timedOut=true` 并以非 0 退出。
- `--predicate` 只支持内置安全函数与布尔组合：`text.exists`、`text.gone`、`exists`、`gone`、`&&`、`||`、`!`，不执行脚本代码。
- `--idle` 使用 AX 可见文本签名连续稳定作为可交互近似信号，避免完整 hierarchy 内部字段波动导致误判。

## Issue #6 evidence bundle export

- 新增 `triton evidence`，用于真实项目回归和 GitHub issue 附件证据包导出；首期证据包是 `.tritonevidence` 目录，固定包含 `manifest.json`。
- 默认采集 `status/list/version/hierarchy/ax/screenshot`；可通过 `--include` 选择 `status,list,version,hierarchy,ax,screenshot,geometry,archive,logs`，当前 embedded runtime 不支持的 `logs` 会进入 `manifest.skipped`。
- `manifest` 记录 `formatVersion`、`artifacts[]`、`skipped[]`、target identity、connection/cache state、CLI version 与 artifact freshness；`triton evidence inspect <dir> --json` 可离线读取 manifest。
- README、`ai-cli-readable-control`、真实项目回归 handoff 与项目级 skills 已同步改为优先使用 `triton evidence --name <case> --output <dir.tritonevidence> --json`。

## CLI duplicate text target disambiguation

- 决策：同页面出现多个相同文案时，保留 `triton tap "<text>"` 选择第一个候选的兼容行为，同时新增机器可读消歧入口。
- `triton find "<text>" --all` 返回 `matchCount` 与 `candidates[]`，每个候选包含 `index/source/strategy/frame/targetOID/viewOID/request`。
- `triton tap "<text>" --index <n>` 按 `find --all` 的 1 起始序号点击；`triton tap "<text>" --within x,y,width,height` 先按区域过滤再选择候选。
- `docs-linhay/scripts/verify-intent-cli-smoke.sh` 已覆盖两个 `hello` 目标的 `find --all`、`tap --index 2` 与 `tap --within`。

## CLI point shorthand sweep

- 交互命令扫描结论：`--within x,y,width,height` 保持区域过滤语义；只需要指定一个点位时新增 `--at x,y`，避免把点位伪装成零尺寸区域。
- `triton find "<text>" --at x,y` 与 `triton tap "<text>" --at x,y` 会筛选 frame 包含该点的同文案候选；`triton tap --at x,y`、`triton hit --at x,y`、`triton paste "<text>" --at x,y`、`triton clear --at x,y` 作为坐标简写，旧的 `--x/--y` 保持兼容。
- `triton press <button>` 新增位置参数入口，`triton press --button <button>` 保持兼容；两者同时提供时返回 validation error。
- 已同步 README、`ai-cli-readable-control`、device control 文档、真实项目回归 handoff 与项目级 skills；`verify-intent-cli-smoke.sh` 覆盖 `find/tap --at`、坐标类 `--at`、`press home` 和 schema 暴露。

## Issue #9 atomic CLI replacement docs

- 风险结论：当 `triton serve` 正从 `~/.local/bin/triton` 等路径运行时，直接 `cp .build/release/triton <active-path>` 覆盖旧文件可能导致后续新进程被 macOS kill，表现为无 stdout/stderr 的 exit 137。
- 决策：所有本地 fallback、手动 release asset 和 skill 中的现有 CLI 路径更新说明，必须推荐先停止 `triton serve`，或使用 `cp .build/release/triton ~/.local/bin/triton.new && mv ~/.local/bin/triton.new ~/.local/bin/triton` 原子替换。
- 已同步 README、Homebrew 发布设计文档、真实项目回归 handoff、`tritonkit-ops-governance`、`tritonkit-dev-feedback` 与 `tritonkit-real-project-regression`。
