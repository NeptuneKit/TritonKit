- 将 `https://github.com/awizemann/harness` 列为参考项目，新增 `docs-linhay/references/harness.md`。
- 结论：Harness 对 TritonKit 的价值不在 GUI 产品形态，而在 UX run / agent loop / evidence 体系：append-only JSONL run log、friction taxonomy、persona + goal 分离、每步 fresh screenshot、observation/intent/action/result、cycle detector、credential redaction、clean screenshot vs agent-only overlay、PlatformAdapter/UXDriving 抽象。

- Evidence 路线补充：后续 `.tritonevidence` 可增加 Harness 风格 run event 子流：`run_started`、`step_started`、`tool_call`、`tool_result`、`friction`、`step_completed`、`run_completed`，并保持 screenshot-before-event、relative path、partial tail tolerant、schema versioned parser 等不变量。

## ai-phone reference research

- 将 `https://github.com/dongxinsuperman/ai-phone` 列为参考项目，新增 `docs-linhay/references/ai-phone.md`。
- 结论：ai-phone 不是 TritonKit 应复制的中台技术栈；按最新边界，它主要作为本机三端模拟器/仿真器 CLI 的 command ledger、执行安全层、AI 可消费 case、batch 和 evidence 参考。
- License 风险：ai-phone 使用 GNU GPLv3，TritonKit 只能借鉴架构和契约，不能直接复制代码。
- 原 `docs-linhay/spaces/20260521-ai-phone-device-cloud/` 经两轮重评估后收敛为 `docs-linhay/spaces/20260521-ai-phone-emulator-cli/`：只做 CLI、只考虑本机 iOS Simulator / Android Emulator / Harmony Emulator，不做 Web、不做真机、不做远端 agent、不做设备云。P0/P1 优先做 filesystem portable command ledger、三端本机 target readiness、execution safety metadata 和 AI case lint。
- 与 Harness 分工：Harness 更强在单次 UX run 的可解释证据；ai-phone 更强在生产化调度、设备池、命令证据链和执行安全层。两者都要落到 TritonKit 的 CLI/HTTP JSON 契约与 `.tritonevidence`，不能反向变成 GUI-first 或中台-first。

## CLI capability admission decision

- 用户明确授权由 Codex 决策“哪些能力进 CLI，哪些不进”，因为这是后续 AI agent 自己要用的工具。
- 决策原则：agent 在一次回归中需要直接观察、准备、执行、验证、归档，或需要稳定 JSON/JSONL、evidence、command ledger、无 UI 复跑的能力，必须进入 `triton` CLI。
- 明确进入 CLI：schema/doctor/capabilities/plan、device list/use/wait-ready/lock/unlock、sim/app lifecycle、runtime ax/find/tap/wait/assert、capture/evidence、command ledger inspect、record/replay、case lint、run submit/status/cancel、agent connect/status/disconnect。
- 只读或非 P0 CLI：本机 device pool list/resolve、run events、checkpoint replay、本地报告生成、bounded logs collect。
- 不进入当前方向：远端 agent、中心 Server、对外 HTTP API、Postgres migration、Kafka/Webhook、Web/运维大盘、多租户权限、全局设备池写入、内置 VLM loop、V2/V3 轨迹自动重定位、系统安全绕过。

- 决策：对外接入使用指南不再只按 iOS 长流程组织；README 和 public skills 必须先分流 iOS embedded runtime、Harmony host-side HDC adapter、Harmony embedded SDK、macOS CLI install/run。
- iOS 口径保持 Debug-only bootstrap：SwiftPM/CocoaPods 接入、独立 `TritonKitDebugBootstrap.swift`、文件级 `#if DEBUG`、Release no-op 但业务 App 入口不能直接导入或启动 TritonKit。
- Harmony 口径拆成两条：host-side DevEco Emulator/HDC 控制不要求 App 集成 SDK；embedded SDK 使用 package id / import path `tritonkit`，Debug-only，Release disabled/no-op，route/responder/semantic action 等业务语义由 App provider 显式提供。
- CLI 口径：released build 默认 Homebrew，未发布源码验证才用 `swift build --package-path CLI --scratch-path .build/cli -c release --product triton`；手动替换 PATH 上二进制时继续要求停止 server 或临时文件加 `mv`。
