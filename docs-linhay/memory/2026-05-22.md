## iOS + Harmony observe / node resolve P0

- 已继续推进 WebView Runtime Bridge S4：`triton observe current/tree` 与 `triton node resolve` 已实现为正式 CLI 契约，覆盖 iOS runtime 与 Harmony host layout。
- iOS 侧 `observe current/tree --platform ios` 通过 DEBUG embedded runtime 的 runtime snapshot / AX 树输出 `runtime-tree` source；`node resolve --platform ios --text <text>` 可按当前 AX 节点解析目标。
- Harmony 侧 `observe current/tree --platform harmony` 通过 HDC `uitest dumpLayout` 输出 `host-layout` source；`node resolve --platform harmony --text <text>` 可按 host layout text/id/key/accessibilityId 解析目标。
- `node resolve` 支持 `--index`、`--within`、`--at`、`--all`，用于避免多候选隐式猜测。
- 新增 `docs-linhay/scripts/verify-ios-runtime-observe-smoke.sh`，用本地 mock embedded runtime 验证 iOS observe / node resolve；`verify-harmony-host-smoke.sh` 已覆盖 Harmony observe / node resolve。
- 真实 Harmony target `127.0.0.1:10100` 已补跑 `observe tree --platform harmony --max-nodes 80` 与 `node resolve --platform harmony --text console --all`：前者返回 `partial=true`、80 个节点、2 个 Web candidate；后者返回 `ok=true`、`matchCount=1`、`node.source=host-layout`。
- 风险结论：真实 Harmony `uitest dumpLayout` / host layout 采集需要串行执行；并发写同一 artifact 曾导致输出污染或 timeout，最终证据以串行重跑的 v02 artifact 为准。
- 边界保持不变：Web provider / DOM / JS / bridge 尚未实现；Web 容器节点只能标记 `candidateOnly=true` 和缺失能力，不能声明页面 bridge 可用。
