## iOS + Harmony observe / node resolve P0

- 已继续推进 WebView Runtime Bridge S4：`triton observe current/tree` 与 `triton node resolve` 已实现为正式 CLI 契约，覆盖 iOS runtime 与 Harmony host layout。
- iOS 侧 `observe current/tree --platform ios` 通过 DEBUG embedded runtime 的 runtime snapshot / AX 树输出 `runtime-tree` source；`node resolve --platform ios --text <text>` 可按当前 AX 节点解析目标。

## Issue 20 tap activation 薄切片

- 在独立 worktree `../TritonKit-worktrees/20260522-issue-20-tap-activation` 处理 GitHub issue #20，分支基线为 `81c5f14`，避免污染主仓当前并行改动。
- 已为 `triton tap "<text>"` 增加 `smart/exact/ancestor` activation strategy；默认 smart 会把文本匹配节点作为 matched node 传给 runtime，由 runtime 向上选择 UIControl、UITableViewCell、UICollectionViewCell 或 tap gesture parent。
- `TKInputResult` 现在可输出 `matchedOID/matchedClassName`、`activationOID/activationClassName` 与 `strategy`，方便 agent 区分“匹配到的文本”和“实际激活目标”。
- 主控评审后补强：query 默认 smart；`--ax-oid` / `--ax-label` 默认 exact，但显式 `--strategy` 会生效；低层坐标 / oid selector 不接受 `--strategy`，避免静默误导。
- 主控评审后补强：UIControl action 改为同步派发并测试 `tapCount`；collection cell selection 补测试；table/collection cell activation 尊重 selection 开关与 delegate selection 门禁。
- Gesture-backed parent 当前返回机器可读 unsupported strategy，不伪造成功；后续如需真实 gesture 派发应单独定义公开 API 边界。
