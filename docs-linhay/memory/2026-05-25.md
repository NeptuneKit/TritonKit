## Simulator Target Simplification

- 已落地统一 host target selector 基础闭环：`.triton/host-targets.json` 保存 alias/current，新增 `device alias list/set/remove`、`device use/current/resolve`。
- `HostDeviceSelector` 支持 alias、`sim:<udid>`、`harmony:<target>`、`triton:ios-simulator:<udid>`、原始平台 id、`booted`、`current`，并支持 `--platform`、`--name`、`--runtime`、`--state`、`--ready` 过滤；多候选保持 `ambiguous_target`，输出 candidates 与 suggestedCommands。
- 常用命令已接入 `--device`：`app launch/open-url`、`device wait-ready/screenshot`、顶层 `screenshot`、`observe current/tree`、`node resolve`。兼容 `--simulator` / Harmony `--target` 保留；与 `--device` 同传返回 `parameter_conflict`。
- 第二轮补齐常用 host app 与 smoke 命令：`app list/info/install/uninstall/terminate/container/prefs` 和 `smoke ios|harmony` 已支持 `--device`，schema examples 默认展示统一 selector，旧 `--simulator` / Harmony `--target` 继续作为兼容路径。
- 收尾门禁发现并修复 host validation 双 JSON 问题：`failHostValidation` 输出 JSON 后抛出的 `ExitCode.failure` 现在由 `failHostCommand` 直接透传，不再追加第二个 `host_action_failed` envelope，保证失败输出仍是单个合法 JSON。
- 会话整理已将该规则沉淀到 `tritonkit-ops-governance`：凡 CLI helper 已输出机器可读 error envelope 并抛 `ExitCode`，外层 catch 必须透传，验证需确认失败输出仍为单个合法 JSON。
