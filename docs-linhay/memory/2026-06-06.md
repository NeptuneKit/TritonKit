## Android app launch 真实回归修复

- 真实 emulator 上，`triton app launch --platform android --device android-a --package-name com.android.settings --json` 原先会卡在不稳定的 `adb shell monkey -p <package> 1`。
- 修复为：
  - 先 `adb shell cmd package resolve-activity --brief <package>`
  - 再 `adb shell am start -n <resolved-component>`
- 相关代码面：
  - `Sources/TritonKitShared/TKAndroidADBSupport.swift`
  - `Sources/TritonKitShared/TKHostAdapterModels.swift`
  - `Sources/TritonKitCLI/CLIHostCommands.swift`
  - `Sources/TritonKitCLI/CLISmokeRuntime.swift`
- 真实验证成功命令：
  - `adb -s emulator-5554 shell am start -n com.android.settings/.Settings`

## Android observe / wait / tap 真实回归修复

- 真实 emulator 上，`uiautomator dump` 的 stdout 只有提示语 `UI hierchary dumped to: /sdcard/window_dump.xml`，真正 XML 在远端文件里。
- 旧实现误把 stdout 当 XML 解析，导致 Android host-side `observe tree`、`wait`、`tap`、`smoke android` 失败。
- 修复为：
  - 先 `adb shell uiautomator dump /sdcard/window_dump.xml`
  - 再 `adb shell cat /sdcard/window_dump.xml`
  - 解析 `cat` 回来的 XML
- 相关代码面：
  - `Sources/TritonKitShared/TKHostAdapterModels.swift`
  - `Sources/TritonKitShared/TKAndroidADBSupport.swift`
  - `Sources/TritonKitCLI/CLIActionCommands.swift`
  - `Sources/TritonKitCLI/CLIObservationRuntime.swift`
  - `Sources/TritonKitCLI/CLISmokeRuntime.swift`
- 真实命令验证已通过：
  - `triton observe tree --platform android --target emulator-5554 --json`
  - `triton tap --platform android --target emulator-5554 'Network & internet' --json`
