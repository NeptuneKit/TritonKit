## Android 支持边界确认

- 用户追问“是否已经完整支持安卓”；结论需要按当前产品边界回答。
- 已完整闭环并发布的是本机 Android Emulator host-side CLI 接管能力：
  - `triton device --platform android` 的 doctor / list / alias / use / wait-ready / screenshot。
  - `triton app --platform android` 的 list / info / install / uninstall / launch / terminate / open-url。
  - Android host-side `observe tree`、`wait`、`tap` 和 `smoke android`。
  - 真实 AVD `Neptune_API_34`、adb serial `emulator-5554`、alias `android-a` 上的 Settings smoke / evidence / screenshot 验收。
  - `v0.1.17` 已发布并包含 macOS arm64 / x86_64 CLI 包、skills 包和 checksum manifest。
- 不应表述为“整个 Android 平台完全支持”：
  - Android 真机、USB 授权、设备农场、远端 adb server、远端 agent 不在当前范围。
  - Android embedded runtime SDK 不在当前范围。
  - Web / Wails UI、多 emulator 并发 UIAutomator 调度、内置智能重定位或 VLM loop 不在当前范围。
- 后续对外口径：说“Android Emulator 接管能力已完整支持并发版”，同时明确它是本机 emulator host-side 支持。

## GitHub #36 iOS Media Playback Helpers

- 线上 issue #36 指向真实 iOS 视频回归缺口：`AVPlayerViewController` 能渲染远端视频，但系统播放控件不稳定暴露为可操作 AX 节点，导致 pause / resume / seek / progress 等断言无法稳定复跑。
- 本轮新增 embedded runtime `snapshot` 的 `media` section：
  - `triton snapshot --include media,ax,screenshot-metadata --json`
  - 输出 AVPlayer-backed surfaces、player status/rate/time/progress、AX control candidates、`automationConfidence`、fallback advice 和 evidence commands。
- `media-playback` 作为 capability matrix 的 observe 能力暴露，`nextAction` 指向 media snapshot；断开 runtime 时仍走 `status` / `serve` 恢复链，不把 media discovery 伪装成 server-independent。
- 交付边界：只使用公开 UIKit / AVFoundation / AVKit API 观测，不声明能可靠操控系统 `AVPlayerViewController` 私有控件；当 `automationConfidence=surface-only` 时，真实项目应加 app-owned DEBUG overlay，并用稳定 accessibility identifiers 暴露 play / pause / seek / progress / elapsed / duration。
- 已同步 README、`tritonkit-dev-feedback`、`tritonkit-real-project-regression`，并建立 `docs-linhay/spaces/20260608-ios-media-playback-helpers/README.md`。

## GitHub #34 App Prefs Data

- issue #34 第一片完成：`triton app prefs get/dump` 对 plist `Data` 输出稳定 JSON envelope `{plistType:"data", base64, length}`，并在 get/dump/set JSON 输出中补充 stored plist type 字段，帮助 agent 避免把 `UserDefaults.data(forKey:)` key 误判或误写成 array/dictionary。
- `triton app prefs set` 新增显式 Data 写入入口：`--type data --base64 <base64>` 或 `--type data --hex <hex>`；默认 `--type json` 仍保持原有 property-list compatible JSON 写入，不自动 preserve 既有 Data 类型。
- 语义边界：本片仍直接编辑 iOS Simulator App data container 下的 preferences plist，通过 Foundation plist serialization 写入 `Data`，未切换为 `defaults write` / CFPreferences 进程调用；真实 simulator 与 `defaults read` 一致性仍需后续 smoke 或 follow-up 覆盖。
- 文档同步：`docs-linhay/spaces/20260608-issue-34-prefs-data/README.md`、README、`docs-linhay/dev/ai-cli-readable-control.md` 与 public skills 已补充 Data prefs 契约。
- 验证通过：`swift test --filter TKHostAdapterModelsTests/preferencePlistDecoding`；在 worktree 内 `.build/issue-34-test-copy/TritonKit` 临时同名副本跑 `swift test --package-path .build/issue-34-test-copy/TritonKit/CLI --scratch-path .build/issue-34-cli-tests --filter HostPreferencesSetTests`（8 tests）和 `swift test --package-path .build/issue-34-test-copy/TritonKit/CLI --scratch-path .build/issue-34-cli-tests --filter SchemaFactSourceTests`（105 tests）。

## GitHub #35 Selector Flags

- 背景：agent-facing host app workflow 已使用 `--device <selector>`，但 embedded observation / action workflow 的 `find`、`tap` 等命令只接受 `--target`，导致 agent 复用 simulator selector 时被 ArgumentParser 拒绝。
- 本轮将 runtime target 参数接入 `--device` alias：`find`、`wait`、`tap`、`swipe`、`type`、`paste`、`clear`、`press`、`geometry`、`accessibility-tree`、`hit`、`input`、`assert` 均保留 `--target` 并接受 `--device`。
- schema 新增 `--target/--device` 机器可读 option，action schema 统一复用该 selector vocabulary；observation schema 在 `find`、`wait`、`geometry`、`hit`、`assert` 等相关 runtime target 命令上暴露同一 option。
- 验收测试新增 `SelectorFlagTests`，覆盖 `Find.parse`、`Tap.parse`、`Wait.parse`、`UIAssert.parse` 的 `--device booted` 解析，以及 `find` / `tap` schema 的 `--target/--device` 暴露。
- 验证：
  - `swift test --package-path CLI --scratch-path .build/cli-tests --filter SelectorFlagTests`
  - `swift test --package-path CLI --scratch-path .build/cli-tests --filter SchemaFactSourceTests`
  - `swift test --package-path CLI`
