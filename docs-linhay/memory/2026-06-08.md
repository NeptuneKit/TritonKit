## Android 支持边界确认

- 用户追问“是否已经完整支持安卓”；结论需要按当前产品边界回答。
- 已完整闭环并发布的是本机 Android Emulator host-side CLI 接管能力：
  - `triton device --platform android` 的 doctor / list / alias / use / wait-ready / screenshot。
  - `triton app --platform android` 的 list / info / install / uninstall / launch / terminate / open-url。
  - Android host-side `observe tree`、`wait`、`tap` 和 `smoke android`。
  - 真实 AVD `Neptune_API_34`、adb serial `emulator-5554`、alias `android-a` 上的 Settings smoke / evidence / screenshot 验收。
  - `v0.1.17` 已发布并包含 macOS arm64 / x86_64 CLI 包、skills 包和 checksum manifest。
- 不应表述为“整个 Android 平台完全支持”：
  - Android 真机、USB 授权、设备农场、远端 adb server、远端 agent 不在当前范围。
  - Android embedded runtime SDK 不在当前范围。
  - Web / Wails UI、多 emulator 并发 UIAutomator 调度、内置智能重定位或 VLM loop 不在当前范围。
- 后续对外口径：说“Android Emulator 接管能力已完整支持并发版”，同时明确它是本机 emulator host-side 支持。

## GitHub #36 iOS Media Playback Helpers

- 线上 issue #36 指向真实 iOS 视频回归缺口：`AVPlayerViewController` 能渲染远端视频，但系统播放控件不稳定暴露为可操作 AX 节点，导致 pause / resume / seek / progress 等断言无法稳定复跑。
- 本轮新增 embedded runtime `snapshot` 的 `media` section：
  - `triton snapshot --include media,ax,screenshot-metadata --json`
  - 输出 AVPlayer-backed surfaces、player status/rate/time/progress、AX control candidates、`automationConfidence`、fallback advice 和 evidence commands。
- `media-playback` 作为 capability matrix 的 observe 能力暴露，`nextAction` 指向 media snapshot；断开 runtime 时仍走 `status` / `serve` 恢复链，不把 media discovery 伪装成 server-independent。
- 交付边界：只使用公开 UIKit / AVFoundation / AVKit API 观测，不声明能可靠操控系统 `AVPlayerViewController` 私有控件；当 `automationConfidence=surface-only` 时，真实项目应加 app-owned DEBUG overlay，并用稳定 accessibility identifiers 暴露 play / pause / seek / progress / elapsed / duration。
- 已同步 README、`tritonkit-dev-feedback`、`tritonkit-real-project-regression`，并建立 `docs-linhay/spaces/20260608-ios-media-playback-helpers/README.md`。
