## GitHub #43 iOS Simulator Host Input

- issue #43 的边界收敛为本机 iOS Simulator host-side setup primitive：`triton sim tap` 与 `triton sim type`，用于 embedded runtime 不可用时帮助 agent 继续完成简单准备动作。
- 公开可落地 primitive 为 `xcrun simctl io <simulator> tap <x> <y>` 与 `xcrun simctl io <simulator> keyboard type <text>`；首期只承诺坐标 tap 与 ASCII text input。
- 新输出模型为 `HostSimulatorInputOutput`，包含 `runtimeScope=host-simulator`、`adapter=xcrun-simctl`、`sourceCommand`、truncation 标记和后续验证提醒。host input 成功只证明命令提交成功，业务状态仍需 `wait/assert/screenshot/app prefs/evidence` 证明。
- 非 ASCII text input 不调用 `simctl`，返回 `unsupported_text_input`；硬件按键、Home/App Switcher、拖拽、多指、长按、IME/组合字符等未用稳定公开命令实现的 primitive 不伪造成成功。
- `triton schema --command sim --json` 暴露 `tap` / `type` subcommands、`host.simulator-input` output contract、`ios-simulator-host-tap` / `ios-simulator-host-type` capabilities；capability group 为 `host`，`requiredBy[]` 覆盖 `action` 与 `smoke`。
- `triton plan ios-smoke --json` 增加 host-side tap/type fallback step，category 跟随 `sim` root 为 `prepare-target`，供 runtime action 被 `server_unavailable` 阻塞时选择。
- worktree 路径名不是 `TritonKit` 时，`swift test --package-path CLI` 会因本地 path dependency identity 变成 worktree slug 而无法解析 `tritonkit`；本轮将 `CLI/Package.swift` 的本地依赖改为 `.package(name: "tritonkit", path: "..")`，让 CLI tests 在 feature worktree 内可复现。
- 验证通过：`swift test --filter TKHostAdapterModelsTests/simctlCommandBuilderP0Argv`、`swift test --package-path CLI --filter SchemaFactSourceTests`、built CLI 的 `schema --command sim` smoke，以及非 ASCII `sim type` 的 `unsupported_text_input` smoke。
