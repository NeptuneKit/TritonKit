## Triton 融合 Baguette host-HID 输入能力

- 用户纠正产品边界：Baguette 是参考项目，TritonKit 需要直接融合其有价值能力，不能让 Web 长期直接依赖 `baguette` 命令。
- 已将 iOS host input 融合点下沉到 Swift CLI：`runWebHostDeviceInput` 对 iOS host target 进入 Triton host-HID adapter，不再返回 unsupported；`/web/input?target=host:ios:<udid>` 不再优先回退 embedded runtime。
- 当前实现参考 Baguette 能力契约：读取 Simulator chrome layout，将 screenshot framebuffer 坐标转换为 host screen points，并执行 tap / swipe；这是 Triton adapter 的实现细节，Web 只看到 `triton serve POST /web/input`。
- Web dev bridge 已移除直接 `baguette tap/swipe` 调用，改为自动拉起或复用 `triton serve --host 127.0.0.1 --port 19421`，再 POST 到 `/web/input?target=host:ios:<udid>`。
- 实测接口返回 `command=triton serve POST /web/input?target=host:ios:60667794-96F8-40E6-8664-85538EC4663E`，stdout 为 `iOS Simulator tap was submitted through Triton host-HID adapter.`；浏览器 Logs 同样显示 Triton host-HID adapter，不再暴露 Baguette 命令。
- 剩余 P0：Swift host-HID adapter 当前仍以 Baguette CLI 作为内部兼容后端；完整移植需要将 `chrome layout`、tap、swipe 的 SimulatorKit/private-symbol bridge 原生落到 Triton Swift 代码中，最终发布包不依赖用户安装 `baguette`。
- 验证记录：`npm run test` 通过 4 tests；`npm run build` 通过；`swift test --package-path CLI --filter SingleDeviceWebPageTests` 通过 16 tests；浏览器截图归档 `docs-linhay/spaces/20260611-web-mock-ui/screenshots/20260612/20260612-web-triton-host-hid-after-v01.png`。
