# 2026-06-12

## GitHub #43 iOS Simulator Host Input

- issue #43 的本机核验发现：当前公开 `xcrun simctl io help` 只暴露 `enumerate`、`poll`、`recordVideo`、`screenshot`、`screenConfig`，没有稳定 tap 或 keyboard type primitive。
- `triton sim tap` 与 `triton sim type` 作为 agent-facing entry 保留，但当前返回 `unsupported_host_input`，避免把外部 fallback 或不存在的 simctl 子命令伪造成 Triton host input 成功。
- 非 ASCII text input 仍先返回 `unsupported_text_input`；ASCII text 在当前 adapter 下返回 `unsupported_host_input`。需要输入时优先走 embedded runtime semantic input、pasteboard flow、app-owned debug hook 或另行验证的 host adapter。
- `triton schema --command sim --json` 暴露 `tap` / `type` subcommands、`host.simulator-input` output contract、`ios-simulator-host-tap` / `ios-simulator-host-type` capabilities；capability group 为 `host`，`supported=false`，`evidence=["unsupported-envelope","command-schema"]`，并保留 schema-backed nextAction。
- `triton plan ios-smoke --json` 增加 host-side input blocker step，category 为 `diagnose`，供 runtime action 被 `server_unavailable` 阻塞时先确认 capability gap，再选择 fallback。
- worktree 路径名不是 `TritonKit` 时，`swift test --package-path CLI` 会因本地 path dependency identity 变成 worktree slug 而无法解析 `tritonkit`；本轮将 `CLI/Package.swift` 的本地依赖改为 `.package(name: "tritonkit", path: "..")`，让 CLI tests 在 feature worktree 内可复现。
- 验证通过：`swift test --filter TKHostAdapterModelsTests/simctlCommandBuilderP0Argv`、`swift test --package-path CLI --filter SchemaFactSourceTests`、built CLI 的 `schema --command sim` smoke，以及非 ASCII `sim type` 的 `unsupported_text_input` smoke。
