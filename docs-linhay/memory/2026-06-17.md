# 2026-06-17

## `triton web` CLI 入口

- 已在 CLI 根命令中新增 `triton web`，把仓库内现有 `Web/` React / Vite Device Hub 收口成正式产品入口，而不是继续依赖仓库脚本。
- 新命令支持 `--root`、`--triton-bin`、`--host`、`--port`、`--install`、`--no-install`、`--print-command`、`--json`；`--print-command --json` 返回机器可读 launch plan，显式暴露 `mode/repoRoot?/webRoot?/bundledWebRoot?/tritonBin/url/installCommand?/command/environment`。
- `triton web` 已从 checkout-only launcher 扩展为双模式：源码 checkout 下 `mode=dev` 启动 `Web/` Vite dev server；GitHub Release / Homebrew 安装下 `mode=packaged` 由 CLI 内置 HTTP 服务提供随包 `web/` 静态产物。
- packaged 服务覆盖 `/`、assets、SPA fallback、`/web/host-targets`、`/web/host-screenshot`、`/web/ios-simulator/*` 与 `/web/host-logs` 只读 bridge；`GET/POST /web/host-input` 均返回 `405 web_host_input_readonly`，不执行输入动作。
- GitHub Actions arm64 / x86_64 release tarball 现在都会先通过 `actions/setup-node@v6` pin Node 24，再构建 `Web/dist` 并复制到 `triton-macos-*/web/`，release asset validation 检查 `web/index.html`；Homebrew formula 会把 `web/` 安装到 `pkgshare/web`，并在 formula test 中验证 `triton web --print-command --json` 返回 `mode=packaged`。
- `docs-linhay/scripts/ci-validate-mode.sh` 已移除 Bash 4 `mapfile` 依赖，本地 macOS bash 3 可以干净复现 validate mode 分类。
- schema / capability 已同步：`triton schema --command web --json` 暴露 `web.launch-plan` output contract，capabilities matrix 新增 `web-device-hub`，nextAction 固定为 `triton web --print-command --json`，归入 bootstrap/observe 边界。
- focused / full 验证已通过：`swift test --package-path CLI --filter WebCommandTests`、`swift test --package-path CLI`、`npm --prefix Web test`、`npm --prefix Web run build`、`TRITON_VERIFY_XCODE=0 docs-linhay/scripts/verify.sh --local`、`docs-linhay/scripts/verify-ci-validate-mode.sh`、`docs-linhay/scripts/verify-homebrew-formula.sh`、`docs-linhay/scripts/verify-release-automation.sh`、`git diff --check`、`docs-linhay/scripts/check-docs.sh`。
