## Issue #64 Web Packaged Symlink 修复

- GitHub Issue #64 指出：Homebrew `triton` 已包含 packaged Web，但当用户 PATH 中额外 symlink 指向 `/opt/homebrew/bin/triton` 时，`triton web --print-command --json` 会因只按 symlink 路径推导资源目录而返回 `web_root_not_found`。
- 修复点：`discoverBundledWebRoot` 现在同时检查当前可执行文件原始路径和 `resolvingSymlinksInPath()` 后的真实路径，再按旁路 `web/` 与 Homebrew `share/triton/web` 布局寻找 `index.html`。
- 新增 `WebCommandTests.webCommandResolvesBundledStaticDistThroughExtraPATHSymlink`，模拟 `<user-local-bin>/triton -> <homebrew>/bin/triton -> ../Cellar/triton/0.1.20/bin/triton`，确认 packaged plan 找到 `Cellar/triton/0.1.20/share/triton/web`，同时保留用户实际调用的 `triton` 路径作为 command/tritonBin。
- 验证：`swift test --package-path CLI --filter WebCommandTests` 通过 12 项。
