## Web Device Hub 本机启动失败治理

- 本机排查确认 `127.0.0.1:34127` 被 PID 61415 的旧 `triton web` 占用，进程仍指向 `/opt/homebrew/Cellar/triton/0.1.22/share/triton/web`；该路径缺少 `index.html`，所以新 `triton web` dev 模式触发 Vite `Port 34127 is already in use`，浏览器访问 `/` 则命中旧服务的 `web_static_asset_failed` JSON。
- 修复 `triton web` 启动韧性：启动前探测目标 host/port，已占用时返回稳定错误 `web_port_in_use`，hint 给出 `lsof -nP -iTCP:<port> -sTCP:LISTEN` 与 `triton web --port <port>` 恢复路径，避免低层 npm/Vite 报错成为第一层输出。
- 修复 packaged static 缺失体验：packaged server 启动前重新校验 bundled web root；运行期若静态资源缺失，浏览器文档路径返回可读 HTML 诊断，保留 `web_static_asset_failed`、缺失路径和恢复命令，API 路径继续保持 JSON envelope。
- 已更新 `docs-linhay/spaces/20260611-web-mock-ui/README.md` 的 BDD 场景、验收标准与实现记录。验证：`swift test --package-path CLI --filter WebCommandTests` 通过 14 tests；`CLI/.build/debug/triton web --json` 在端口占用状态下返回单个 `web_port_in_use` JSON envelope。随后停止 stale PID 61415，短暂启动 `CLI/.build/debug/triton web --no-install`，`/` 返回 `200 text/html`；验证后停止 Vite 子进程，34127 当前无 listener。
