# 2026-06-20

## Hierarchy viewer 显示 UIViewController 节点

- 用户要求 view-tree 中也显示 `UIViewController`。
- 根因：iOS runtime 已在 `TKDisplayItem.hostViewControllerObject` 暴露控制器对象，但 CLI legacy iOS scene 与 Web dev bridge fallback 之前只把它作为 class fallback，控制器不会成为独立树节点。
- 已在 CLI 转换层和 Web dev bridge 转换层插入 `ios:controller:<oid>` 语义节点，字段包含 `source=runtime-controller`、`raw.role=UIViewController`、`style.display=controller`、`renderHints.preferredMode=structure`。
- 实际 view/layer 节点挂到对应 controller 下；同一 controller 子树内不重复插入控制器节点。只有 runtime DTO 提供 `hostViewControllerObject` 时才显示，不在 Web 端伪造。
- 验证：`node --test --test-name-pattern='falls back to legacy iOS runtime hierarchy and converts it to a Web scene' dev/iosSimulatorBridge.test.mjs` 通过；`npm --prefix Web run build` 通过；`swift test --package-path CLI --filter HierarchySceneRuntimeTests` 3 个用例通过。
- 浏览器复验：重启 `34127` Vite dev server 后，当前 simulator view-tree 出现 `MainTabBarController#12`、`AppNavigationController#585`、`PhotosViewController#592`、`UITrackingElementWindowController#442`、`UIEditingOverlayViewController#447` 五个 `ios:controller:*` 节点；节点数 `433 -> 438`，横向溢出 `0`。

## 模拟器壳标注当前 UIViewController

- 用户确认采用更好的 runtime 事实优先方案，不从 screenshot 或 wrapper view 猜当前 controller。
- `TKHierarchyScene` 增加可选 `controllerContext`，字段包含 active controller id/name/class、controller stack 和 source。
- iOS embedded runtime 的 hierarchy 响应现在复用 UIKit route 解析逻辑，按 root / presented / tab selected / navigation top / split / page / custom visible child 生成 `runtime-route` controller stack。
- CLI legacy iOS scene 和 Web dev bridge 都支持旧 runtime fallback：如果 payload 没有 `controllerContext`，则从 `ios:controller:*` / `runtime-controller` 节点生成 `scene-controller-node-fallback`。
- Web 设备壳新增 `controller-shell-badge`：优先显示当前选中节点所属 controller，否则显示 runtime active controller；fallback 会显示 `fallback` 标记。
- 验证：`swift test --package-path CLI --filter HierarchySceneRuntimeTests` 通过；Web bridge / DOM 目标测试 2/2 通过；`npm --prefix Web run build` 通过；in-app browser 当前 simulator 页面显示 `UIViewController · PhotosViewController fallback`，横向溢出 `0`。

- 会话沉淀识别出的复用模式：Web mock 上的可见语义标签如果依赖 runtime state，必须先由 CLI / HTTP / runtime DTO 提供机器可读字段，Web 只读消费。
