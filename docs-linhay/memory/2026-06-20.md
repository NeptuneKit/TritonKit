## Hierarchy viewer 显示 UIViewController 节点

- 用户要求 view-tree 中也显示 `UIViewController`。
- 根因：iOS runtime 已在 `TKDisplayItem.hostViewControllerObject` 暴露控制器对象，但 CLI legacy iOS scene 与 Web dev bridge fallback 之前只把它作为 class fallback，控制器不会成为独立树节点。
- 已在 CLI 转换层和 Web dev bridge 转换层插入 `ios:controller:<oid>` 语义节点，字段包含 `source=runtime-controller`、`raw.role=UIViewController`、`style.display=controller`、`renderHints.preferredMode=structure`。
- 实际 view/layer 节点挂到对应 controller 下；同一 controller 子树内不重复插入控制器节点。只有 runtime DTO 提供 `hostViewControllerObject` 时才显示，不在 Web 端伪造。
- 验证：`node --test --test-name-pattern='falls back to legacy iOS runtime hierarchy and converts it to a Web scene' dev/iosSimulatorBridge.test.mjs` 通过；`npm --prefix Web run build` 通过；`swift test --package-path CLI --filter HierarchySceneRuntimeTests` 3 个用例通过。

## 模拟器壳标注当前 UIViewController

- 用户确认采用更好的 runtime 事实优先方案，不从 screenshot 或 wrapper view 猜当前 controller。
- `TKHierarchyScene` 增加可选 `controllerContext`，字段包含 active controller id/name/class、controller stack 和 source。
- iOS embedded runtime 的 hierarchy 响应现在复用 UIKit route 解析逻辑，按 root / presented / tab selected / navigation top / split / page / custom visible child 生成 `runtime-route` controller stack。
- CLI legacy iOS scene 和 Web dev bridge 都支持旧 runtime fallback：如果 payload 没有 `controllerContext`，则从 `ios:controller:*` / `runtime-controller` 节点生成 `scene-controller-node-fallback`。
- Web 设备壳新增 `controller-shell-badge`：优先显示当前选中节点所属 controller，否则显示 runtime active controller；fallback 会显示 `fallback` 标记。
- 验证：`swift test --package-path CLI --filter HierarchySceneRuntimeTests` 通过；Web bridge / DOM 目标测试 2/2 通过；`npm --prefix Web run build` 通过；in-app browser 当前 simulator 页面显示 `UIViewController · PhotosViewController fallback`，横向溢出 `0`。

## 模拟器壳 controller 类名不截断

- 用户指出模拟器壳上的 `UIViewController` 类名会被截断，当前原因是 `.controller-shell-badge strong` 使用单行省略号。
- 处理边界限定在 Web mock 设备壳：类名标注移到模拟器壳上方，只显示可读的自定义 controller 类名，支持文本选择 / 复制，占满可用宽度并允许换行；Swift 私有 mangled 类名会提炼为可读后缀类名，`title` 继续保留完整 controller stack。
- 不改变 runtime fact source、`HierarchyScene.controllerContext`、view-tree 数据或 CLI / HTTP 契约。

## Overloaded 本地联调：iOS Simulator runtime input

- 用户在 Web Device Hub 联调 Overloaded 时发现 `longPress` 没有及时触发，并返回 `runtime input longPress iOS Simulator host-side longPress is not exposed in the Web device surface yet`。
- 根因拆成两层：
  - Web canvas 只在 `pointerup` 后按按住时长判断 `longPress`，导致长按不会在阈值到达时及时提交。
  - iOS Simulator target 的输入请求默认沿用 `screenshotSource=host`，`longPress` / `pinch` 会落到 host-side adapter；该 adapter 对这些手势没有公开实现，应该改走 embedded runtime。
- 修复：
  - Web `SingleGestureState` 增加 `longPressDispatched`，在 520ms 阈值到达且指针未移动超过 tap threshold 时立即发送 `longPress`；`pointerup` 只清理预览，不再重复发送或退化成 tap。
  - Web `sendHostInput` 对 iOS Simulator 的 `longPress` / `pinch` 强制设置 `source=runtime`。
  - Swift packaged Web bridge 的 `/web/host-input` 解析 `target`，并通过 `/targets` 将 `sim:<UDID>` 映射到具体 `triton:ios-simulator:<UDID>`，避免多 runtime target 时 ambiguous。
  - embedded runtime 新增公开 UIKit 边界内的 `performLongPress`：命中 `UIControl` 时发送 `.touchDown`、等待 `duration`、再发送 `.touchUpInside`；命中仅有 `UILongPressGestureRecognizer` 的视图时返回公开 API 边界错误，不做私有 target-action 反射。
  - embedded runtime 新增 `performPinch`：命中 zoomable `UIScrollView` 时调整 `zoomScale`，否则返回 `zoomable-scroll-view-required`。
- 现场验证：
  - `node --test --test-name-pattern "dispatches canvas long press and pinch gestures" Web/dev/appFallbackDom.test.mjs` 通过，证明长按在 `pointerup` 前已发送且 `source=runtime`。
  - `node --test --test-name-pattern "dispatches iOS Simulator runtime long press" Web/dev/iosSimulatorBridge.test.mjs` 通过，证明 dev bridge 能把 Simulator UDID 映射到 runtime target。
  - `npm run build`、`swift build`、`swift build --package-path CLI --scratch-path .build/cli -c debug --product triton`、`git diff --check` 均通过。
  - 通过 `triton xcode run` 将 Overloaded 重新 build/install/launch 到 simulator `1B360513-22E7-46DB-A942-198EE522C6DC`，launch PID `29174`。
  - 实测 `curl /web/host-input?...source=runtime` 长按 `_UITabButton` 返回 `ok=true`、`message=Submitted UIControl long press touch events`、`strategy=control-long-press-touch-events`。
- 已知阻塞：`swift test --filter TKRuntimeInputActionsTests` 会编译整个 root test target，当前被既有 `Tests/TritonKitSharedTests/TKXcodeWorkflowModelsTests.swift` 编译错误阻塞；该阻塞不是本轮 input 修复引入。
- 模式沉淀：Web canvas 可以采集人类手势，但手势路由必须根据 host/runtime 能力边界选择事实入口；host-side 已明确 unsupported 的手势不应在 Web 层继续伪装成 host 能力，应该转交 embedded runtime 并保留公开 API 边界错误。
