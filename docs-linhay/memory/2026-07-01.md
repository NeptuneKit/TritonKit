## 移除 Web 窗格中重复卡片类型载入限制

- 修复了用户在多窗格布局（Web 控制台）中无法载入两个或多个同类型卡片的问题。
- 移除了 `App.tsx` 的 `NodeRendererProps` 与 `NodeRenderer` 中多余的 `activeCardTypes` 属性和接口定义，简化了组件传递逻辑。
- 移除了卡片挑选界面中的去重提示（“已载入”）以及 `isLoaded` 限制，现在用户可以在不同的插槽中自由选择并载入相同的卡片（例如打开两个 Simulator 监控卡片）。
- 本地在 `Web/` 目录下运行 `npx tsc --noEmit` 验证通过，没有 TypeScript 编译报错。

## 重构窗格工具栏（PaneToolbar）样式与按钮

- **修复按钮字符溢出重叠**：原先采用纯文本 `⟵⟶` 做分割按钮，字符过宽超出了 22px 按钮宽度限制。已将其替换为 `lucide-react` 中的 `<Columns />`（左右分割）和 `<Rows />`（上下分割），关闭按钮也统一为 `<X />` 图标。
- **解决右上角元素重叠遮挡**：微调了绝对定位偏移，并重构了工具栏 `.pane-toolbar`。移除了按钮上繁杂 of 独立框线，改为由悬浮板自身承载统一的暗色微磨砂毛玻璃底色、1px 微光边框和圆角阴影。
- **优化视觉干扰**：按钮缩小至 `20px`，平时呈现 `0.8` 优雅透明度，只在 hover 时高亮聚焦，使得整个窗格操作台显得非常精致、大方，并且彻底避开了卡片内部右上角 `extra` 元素的遮挡。

## 设备实时画面流（StreamCard）高帧率模式支持

- **后端支持动态 FPS 请求**：修改了 [iosSimulatorBridge.mjs](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/dev/iosSimulatorBridge.mjs) 中的 `/web/ios-simulator/mjpeg` 服务端，引入 `fps` 参数，能基于请求动态计算帧率间隔。
- **混合通道刷新率分流策略**：
  - 如果是极速内存缓存通道（19421 端口极速流），帧间隔由用户请求的 FPS 动态决定（最高 60 FPS）；
  - 如果是慢速进程通道（simctl 截图），依然强制采用 1200ms 安全延时，从根本上防止多次高频启动子进程引发的 simctl 死锁。
- **前端增加帧率控制器**：修改了 [StreamCard.tsx](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/src/components/StreamCard.tsx)，设备选择栏新增了 `1 FPS`, `5 FPS`, `15 FPS`, `30 FPS`, `60 FPS` 帧率调节下拉框。当用户调整帧率时，实时重连最新的 MJPEG 流，完美同步刷新频率。
