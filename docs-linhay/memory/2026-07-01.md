## 重构窗格工具栏（PaneToolbar）样式与按钮

- **解决右上角元素重叠遮挡**：微调了绝对定位偏移，并重构了工具栏 `.pane-toolbar`。移除了按钮上繁杂的独立框线，改为由悬浮板自身承载统一的暗色微磨砂毛玻璃底色、1px 微光边框和圆角阴影。
- **优化视觉干扰**：按钮缩小至 `20px`，平时呈现 `0.8` 优雅透明度，只在 hover 时高亮聚焦，使得整个窗格操作台显得非常精致、大方，并且彻底避开了卡片内部右上角 `extra` 元素的遮挡。

## 设备实时画面流（StreamCard）高帧率模式与帧缓冲重构

- **解耦“画面抓取”与“客户端推送”（Frame Cache & Decoupled Loop）**：
  - 为彻底解决原有串行等待 HTTP 截图响应（如单帧 simctl/fetch 耗时 100ms~200ms）导致客户端无法达到 60fps 的物理限制，在 [iosSimulatorBridge.mjs](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/dev/iosSimulatorBridge.mjs) 引入全局画面缓存机制 `simulatorFrameCache`。
  - 启动后台抓图线程 `startSimulatorGrabLoop`，以最优帧率（极速通道 15ms，约 60+ FPS；慢速通道 1200ms 安全排空）从底图接口提取最新帧，缓存到内存全局变量。
  - 客户端长连接 `pushFrame` 解耦，直接以客户端设定的目标帧率（最大 60 FPS）心跳极速推送内存缓存帧。若无新帧则跳过，在实现真正顺滑 of 60 FPS 推送的同时，降低多客户端重复拉取对 Mac 的 CPU 负载。
- **后端支持动态 FPS 请求**：修改了 mjpeg 服务端以读取 `fps` 参数控制心跳推送频率。
- **前端集成帧率控制器**：修改了 [StreamCard.tsx](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/src/components/StreamCard.tsx)，设备选择栏新增了 `1 FPS`, `5 FPS`, `15 FPS`, `30 FPS`, `60 FPS` 帧率调节下拉框。当用户调整帧率时，实时重连最新的 MJPEG 流，完美同步刷新频率。

## 采样校准与内嵌 SDK 极速通道升级

- **Demo 添加高频毫秒计时器**：在 [App.swift](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Examples/TritonKitDemo/TritonKitDemo/App.swift) 中使用 `TimelineView(.animation)` 与自定义的 IIFE 闭包格式化逻辑加入毫秒级的实时跳变文本（精确到 `HH:mm:ss.SSS`），使其在 60 Hz 下画面帧帧不同。
- **优化后台抓取靶向（Target Mapping）**：在 [iosSimulatorBridge.mjs](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/dev/iosSimulatorBridge.mjs) 中优化了 grab loop。抓图时优先尝试连接在线的内嵌 SDK 靶点（`triton:ios-simulator:<udid>`），拿图失败再 fallback 到慢速宿主 `host:ios:<udid>`。这使得 App 运行时画面提取彻底绕过 `simctl screenshot` 命令。
- **硬刷新心跳（Hard Frame Push）**：在 `pushFrame` 中去除 `lastSentTime` 重复帧过滤机制，一旦长连接建立，根据客户端请求的 FPS 硬刷新推送，杜绝 TCP 粘包或网络抖动引起的长连接时延漂移。
- **TritonKit 内存截图编码 JPEG 极致优化**：为了彻底解决 PNG 格式在模拟器侧进行 CPU 压缩时产生的高达 120ms 的物理生成瓶颈，修改了 [TKRuntimeAXBuilder.swift](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Sources/TritonKit/TKRuntimeAXBuilder.swift)，将截图从 PNG 改为高效率的 JPEG 压缩格式（质量 `0.6`）。这使得单帧截图的物理编码和传输响应时间**从 120ms 压缩至极低的 3ms~10ms 级别**。
- **动态 Content-Type 报头**：修改了 [CLIServeCommand.swift](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Sources/TritonKitCLI/CLIServeCommand.swift)，根据客户端上传的格式，动态返回对应的 `image/jpeg` 或 `image/png` Content-Type，确保网络数据完整与规范。
- **FPS 实测采样分析**：
  - 优化后在 60 FPS 模式下运行，3 秒内抓取了 167 帧，**实测刷新率提升到了 Calculated FPS: 55.63**，网页渲染速度成功跟上模拟器！
