## 实时画面层与高亮图层物理贴合及坐标对齐修复

- **定位并根治高亮框不贴合与偏移问题（Resolution of Stream Overlays & Coordinate Alignment Deviation）**：
  - **根本原因定位**：当设备长宽比（Retina `@3x` 对应的 `1206x2622` 图像物理分辨率，以及逻辑屏幕尺寸 `402x874`）被浏览器使用 `object-fit: contain` 放入 `1390x737` 的视口区域时，由于 `object-fit` 内部极其复杂的等比收缩与上下居中逻辑，使得实际显示的图像内容尺寸被浏览器渲染为 `300x651` 并产生垂直 and 水平偏移。然而，高亮 Overlay 容器仍使用了计算所得的 `339x737` 区域进行渲染，导致了整体错位。
  - **解决方案实现**：修改了 [StreamCard.tsx](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/src/components/StreamCard.tsx)。将 `<img>` 标签的 `width / height / left / top` 在 inline style 中手动绑定到经过比率折算计算出的 `imgLayout`，并将 `objectFit` 从 `contain` 改为 `fill`。这使得浏览器渲染出的 `<img>` 画面本身在物理位置和大小上同 Overlay 容器完全一致，实现了真正的物理贴合。
  - **验证结果**：利用 Playwright 运行 [test_overlay.mjs](file:///Users/linhey/.gemini/antigravity-cli/brain/4198961d-50c6-4cf6-bde2-997d5ece5369/scratch/test_overlay.mjs) 脚本，成功在 `screenshot.png` 中观察到所有的页面视图/AX 层次高亮框（如 Status Bar, Dynamic Island, WebView 文本段以及底部 tabbar）**100% 像素级贴合**，无任何方向和比例偏移。

## 解决画面卡片头部控制按钮与面板工具栏重叠问题

- **界面控件层叠与遮挡修复（StreamCard Header Overlay Mode Button Overlapping Fix）**：
  - **问题分析**：在 Web 仪表盘的多面板布局中，每个被填充的卡片槽（`.filled-pane`）的右上角都绝对定位悬浮了一个卡片操作工具栏（`.pane-toolbar`，包含分栏、关闭等按钮，尺寸约为 `97px` 宽）。而 `StreamCard` 的头部控制按钮（无/视图/AX `Radio.Group` 与状态 `Tag`）同样渲染在右上角，导致二者相互重叠、无法看清且无法点击。
  - **解决方案**：修改了 [StreamCard.tsx](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/src/components/StreamCard.tsx) 第 264 行。将头部右侧控制项容器的样式加上 `paddingRight: 100`，使这些控件在视觉上向左平移 `100` 像素，完美为右上角悬浮的 `.pane-toolbar` 腾出空间，彻底解决了遮挡重叠问题。

## 界面与 AX 审查过滤不可见节点优化

- **屏蔽未呈现在屏幕上的隐藏节点（Filter Out Invisible/Hidden Nodes from Hierarchy Trees & Overlays）**：
  - **问题分析**：iOS 应用在运行期可能在窗口（UIWindow）树中挂载部分隐藏的辅助容器或调试面板（例如 APM/内存泄漏监控相关的 `AMMemoryLeakView` 及其下属 `UITableView`、`UITableViewCell` 节点）。虽然这些节点当前正处于隐藏状态（`isHidden: true, alpha: 0`），即在模拟器屏幕上完全不显示、用户也无法交互，但由于原代码没有对隐藏状态做拦截，导致在 Web 端的“视图树”和“AX 树”中仍然被完整地勾勒出节点并绘制了高亮定位框，给用户带来了“界面明明没有表格却探测到了表格”的困惑。
  - **解决方案**：
    * **后端桥接层递归判定**：修改了 [iosSimulatorBridge.mjs](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/dev/iosSimulatorBridge.mjs)。引入 `parentVisible` 并通过递归 `context` 向下层级透传。当父容器本身隐藏时，强行将其子代所有子视图（即使子视图局部没有显式设置 `isHidden`）的 `visible` 属性统一覆盖判定为 `false`。
    * **前端高亮图层过滤**：修改了 [StreamCard.tsx](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/src/components/StreamCard.tsx) 的 `nodesToRender` 过滤器：在渲染画面 Overlay 高亮框前，强加入 `if (node.visible === false) return false;` 剔除隐藏节点。
    * **前端结构树过滤**：修改了 [InspectorCard.tsx](file:///Users/linhey/Desktop/linhay-open-sources/TritonKit-worktrees/20260630-web-redesign/Web/src/components/InspectorCard.tsx) 的节点解析逻辑：在 `flatNodes.forEach` 生成渲染节点映射表前，过滤 `if (node.visible === false) return;` 屏蔽隐形树节点，并追加 `if (!treeNode) return;` 保护子节点连接器，保证当父代隐藏时整条非活动链优雅地被折叠且不发生链接悬空错误。
