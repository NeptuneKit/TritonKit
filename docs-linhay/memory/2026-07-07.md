## Workspace Run Provider Preflight

- `workspace run` 已从硬编码 provider missing 推进到显式 LLM/VLM provider preflight：CLI 支持 `--llm-provider mock --vlm-provider mock`，HTTP `POST /workspace/run` 支持 `llmProvider: "mock"`、`vlmProvider: "mock"`。
- `mock` 作为本地 deterministic LLM/VLM preflight provider 会记录 `providersReady=true`、`providerStatus=ready`，`provider.checked` phase 为 `ready`，`flow.bootstrap.checked` phase 为 `provider_ready`；这仍只是 preflight，不代表真实模型 request/response 已接入。
- `mock` 作为本地 deterministic VLM provider 会记录 `vlmProviderStatus=ready`；因为 LLM provider 尚未配置，整体仍返回 `providersReady=false`、`providerStatus=partial`、`llmProviderStatus=missing`，并给 `configure_llm_provider` nextAction。
- VLM-only preflight 的 provider evidence 和事件流会写入对应事实：`evidence/model/provider-check.json` 记录 provider 状态，`provider.checked` phase 为 `vlm_ready_llm_missing`，`flow.bootstrap.checked` phase 为 `llm_missing`。
- `mlx-swift-lm` / `openai-compatible` 在 workspace preflight 中暂不伪装 ready：缺模型或 base URL 时只返回配置 nextAction；真实 request/response 和模型参与仍待后续切片接入。

- `workspace run` 的 `atlas/atlas.json` 已从空壳推进到 run-local 初始 Atlas seed：包含 `kind=triton.workspace.atlas`、`runId`、`screen_0000`、`state_0000`、coverage 计数和 `events.jsonl#observation.captured` / screenshot / hierarchy evidence backlink。
- `--dry-model-fixture` 现在会写回 Atlas transition：`atlas/deltas.jsonl` 和 `atlas/atlas.json` 都包含 `transition_0000`，状态为 `candidate_failed`，从 `screen_0000` 回到 `screen_0000`，并引用 model / policy / action / verify evidence。
- `workspace export-flow` 会从 `action.executed` 事件派生最小 action step；dry fixture 当前可导出 `tap Continue`，并保留 model / policy / verify evidence backlink。
- `workspace inspect` 现在返回 Atlas summary：`atlasRef`、`deltaRef`、`coverageStatus`、`screenCount`、`stateCount`、`transitionCount`，HTTP inspect 复用同一响应。
- 当前 Atlas / flow 仍未做真实 observation 驱动的 transition、state variant 合并、路径 coverage 或 app-map merge；下一步应从真实 action 前后 observation 和 `atlas.updated` 事件生成 transition delta。

## Workspace Run Runner Bounds

- `workspace run` 现在把自主探索 loop 的边界写成机器可读 `runner` 契约：`actionPolicy`、`maxSteps`、`allowedActions`、`stopConditions` 会进入 `run.json`、`report.json` 和 `config.yaml`。
- 默认 runner 边界是 `maxSteps=20`、`allowedActions=[tap,swipe,type,wait,verify,stop]`、`stopConditions=[max_steps_reached,provider_missing,unsupported_capability,policy_rejected,model_unparseable]`；这为后续真实 LLM/VLM loop 提供停止条件，避免无界探索。
- CLI 支持 `--max-steps`、可重复 `--allowed-action`、可重复 `--stop-condition`；HTTP `POST /workspace/run` 支持 `maxSteps`、`allowedActions`、`stopConditions`，两者复用同一 runtime 校验。
- 非法 `maxSteps <= 0` 会抛出 `RuntimeError`，不会创建 run；schema 已同步暴露 runner options。
- 已验证：先跑红灯确认 `runner` 字段不存在，再实现后通过 `swift test --package-path CLI --filter WorkspaceRunTests`。

## Workspace Run Policy Gate Dry Path

- `--dry-model-fixture` 现在会把模型候选 `tap Continue` 先交给 runner allowlist；当 `allowedActions` 不包含 `tap` 时，`policy.checked` 写 `failed`，`evidence/model/policy-000.json` 写 `stopReason=policy_rejected`。
- policy 拒绝时不会写 `action.executed`、`verify.checked`、`atlas.updated`、`atlas/deltas.jsonl` 或 `evidence/actions/action-000.json`；Atlas coverage 保持初始 seed，避免把被拒动作误记成 transition。
- 拒绝路径仍会写 `model.decided`、`policy.checked`、`flow.recovery.detected(policy_rejected)` 和 `flow.recovery.proposed(stop)`，让后续 LLM/VLM recovery 设计有可追溯事实流。
- 已验证：先跑红灯确认固定 allowed=true 的旧路径会错误执行 action，再实现后通过 `swift test --package-path CLI --filter WorkspaceRunTests`。

## Workspace Run Paused Lifecycle

- Shared event protocol 新增 `TKTestRunStatus.paused` 与 `run.paused`，parser summary 现在把 `run.finished`、`run.paused`、`run.stopped` 都视为 terminal status source。
- `workspace run` 在 provider missing / LLM missing 时返回 `status=paused` 并以 `run.paused` 收尾；policy reject dry path 也以 `run.paused phase=policy_rejected` 收尾，不再伪装成正常 stopped。
- `workspace stop` 仍负责显式把 run 转成 stopped：如果最后事件不是 `run.stopped`，会追加 `run.stopped` 并把 `run.json` status 写成 `stopped`。
- schema 已同步暴露 workspace run 的 final event 为 `run.paused|run.stopped`，output contract 说明 `summary.status` 可来自 paused terminal event。
- 已验证：`swift test --package-path CLI --filter RunEventWriterTests`、`swift test --package-path CLI --filter WorkspaceRunTests`。
