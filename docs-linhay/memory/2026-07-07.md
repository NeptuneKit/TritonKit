- assertion 模式要求 `--business-ready-text <text>`，通过 runtime verify text-exists assertion provider 读取当前 runtime accessibility tree 并调用 `TKUIAssertEvaluate`；artifact 写入 `check=runtime_assert`、`source=runtime.assert`、`phase=assertion_passed|assertion_failed` 或 action 后的 `post_action_assertion_passed|post_action_assertion_failed`，并嵌套 assertion evidence。
- `--execute-actions --business-ready-assert` 会在 action 成功后执行 assertion checkpoint；通过时写 `business.ready` / `verify.checked`，run 以 passed 收尾，Atlas transition 标记 `verified`。失败且 `--observe-live --max-steps N` 仍有预算时，复用 bounded recovery loop，从最新 post-action observation 继续下一轮 decision/action/verify。
- schema、README、agent-facing CLI 文档、`20260706-agent-mobile-runtime-platform` space、技术方案、内部 MLX/VLM skill 和 public emulator takeover skill 已同步。
- 已验证：先补红灯 `workspace run verifies business readiness through assertion provider after action`，旧实现缺 `businessReadyAssert`、assert request/provider 编译失败；实现后 `WorkspaceActionExecutionTests`、`WorkspaceBusinessReadinessTests`、`WorkspaceRunTests` focused suite 通过。

## Workspace export-flow to tritontest

- `workspace export-flow` 不再导出内部 `triton.workspace.flow` seed，而是直接写可被 `triton test validate/run` 消费的 deterministic `.tritontest.yaml`。
- 导出内容当前包含 `launch`、`takeScreenshot`、从 `action.executed` 派生的 action steps，并在 run 带 `businessReadyText` 时追加 `assertVisible` 业务 checkpoint；`TKWorkspaceExportFlowResponse.stepCount` 现在返回实际 `.tritontest.yaml` step 数。
- 产品判断：当前优先复用已有 `.tritontest.yaml` validator / runner 作为“探索 -> 可回放”的落地入口，独立 `triton flow validate` DSL 暂不作为本轮实现前提。

## Workspace export-flow preserves VLM grounding

- `workspace export-flow` 现在会读取 `action.executed.ref` 对应的 `evidence/actions/action-<step>.json`；若 action artifact 写了 `usedVLMGrounding=true`，导出的 `.tritontest.yaml` tap step 使用 `target`、`grounding: vlm`、`provider`，并保留可用的 `model/modelPath/allowModelDownload`。
- 响应新增 `requiresVLM` 与 `suggestedCommands[]`；当 seed 需要 VLM 时，建议的 `triton test run ...` 命令会自动包含 `--allow-vlm`，保留 test runner 的显式授权 gate，同时避免 agent 忘记复跑参数。
