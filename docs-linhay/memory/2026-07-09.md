## Packaged Web MJPEG bridge repair

- 用户反馈安装 `triton` `0.2.9` 后，`http://127.0.0.1:34127/` 能显示 AX 树但左侧实时画面空白；浏览器检查 `<img>` 尺寸正常但 `naturalWidth/naturalHeight=0`。
- Triton-first 排查确认 `triton status --json` 可达、runtime connected，但 `34127` 监听者是 packaged `triton web`，直接请求 `/web/ios-simulator/mjpeg` 与 `/web/ios-simulator/frame` 返回 `404`。
- 新增 `docs-linhay/spaces/20260709-packaged-web-mjpeg/README.md` 记录 BDD、范围与验收；修复方向是补 packaged Web server 的只读 iOS Simulator MJPEG/frame bridge，不扩大 Web 控制面。
- 在 `CLIWebRuntime.swift` 中复用 `CLIHostSimulatorFramebufferService`，新增 `/web/ios-simulator/mjpeg` multipart JPEG 流和 `/web/ios-simulator/frame` 单帧兜底；请求解析支持 `udid`、`target=host:ios:<udid>`，并将 FPS 约束在 `1...120`。
- 新增 `WebCommandTests/packagedWebIOSSimulatorMjpegRequestNormalizesTargetAndFps`，红灯表现为 helper 缺失编译失败，绿灯后 focused test 通过。
- 用当前构建的 packaged server 在备用端口 `34129` smoke：无参数 MJPEG 请求返回 `400 invalid_query`，带当前 simulator UDID 请求返回 `200 OK` 与 `multipart/x-mixed-replace; boundary=tritonboundary`，5 秒内收到约 12.7 MB stream 数据并成功抓到首帧。
