## WebView-aware agent tap

- 针对 native AX hit-test 只能命中 `WKWebView` 容器、无法命中 H5 内按钮的问题，技术方案收敛为 agent 继续使用高层 `triton act tap`，通过 opt-in `--webview-aware` 进入 WebView DOM action，不暴露低层 `webview click` 作为主入口。
- 新增方案文档 `docs-linhay/spaces/20260521-ios-embedded-sdk-expansion/technical-research-webview-aware-act-v01.md`，明确首期只做 CSS selector DOM tap + 可选 `expect-text` 验证；`expect-request`、CDP/远程调试和真实 trusted click 后续单独切片。
- Runtime 新增 `webview.tap` request type、HTTP route、capability gate、ledger/action summary 和 WebView provider script；脚本只接受 JSON 编码 selector，滚动目标进视口、检查可见/禁用状态，触发 `mousedown`/`mouseup`/`click` 和 `element.click()`，并在响应中标记 `trusted=false`。
- CLI 新增 `triton act tap --webview-aware --selector ... --webview-id ... --page-session-id ... --expect-text ... --json`，输出 `passed`/`failed`/`uncertain`，无显式验证时不宣称成功，失败时给出 native coordinate 或 snapshot/wait 复查命令。
- 同步更新 `TritonKit.skills/tritonkit-emulator-cli-takeover` 与 `.agents/skills/tritonkit-ops-governance`，沉淀 WebView-aware tap 的 agent 入口、`trusted=false` 和无验证 `uncertain` 语义。
- 验证通过：WebView shared/runtime focused tests 12 个、CLI schema/capability/agent contract focused tests 142 个、`git diff --check` 与 `docs-linhay/scripts/check-docs.sh`。全量 CLI 并发测试仍有既有 fake host command / proxy serve 超时和 connection refused 波动，相关失败套件隔离复跑通过，未见 WebView-aware 新失败。

## CLI full-test concurrency repair

- 解决 WebView-aware tap 收尾时暴露的全量 CLI 并发测试失败：`SimulatorAdvancedControlsTests` 中 host command stdin/stdout/artifact 相关用例在全量并发下超时，`DeviceCrossPlatformTests` 中 proxy serve 用例偶发 `Connection refused`。
- 根因收敛为两类测试基础设施问题：`runHostCommand` / `runHostCommandWritingStdoutArtifact` 使用 `DispatchQueue.global` 执行阻塞式 pipe drain 与 `waitUntilExit`，全量测试并发时容易被其他阻塞任务挤占；proxy serve 测试用 `bind(0)` 拿到端口后立即释放，同一 test runner 内并发用例可能复用端口。
- 修复 `CLIHostProcessRuntime.swift`：为 host command pipe drain / interrupt 使用专用 concurrent queue，并改用 `Process.terminationHandler` 作为进程退出信号，避免额外占用 global worker 等待 `waitUntilExit`。
- 修复 `DeviceCrossPlatformTests.swift`：为测试端口分配增加进程内 reservation set，防止并发 proxy serve 用例拿到重复端口。
- 同步更新 `.agents/skills/tritonkit-ops-governance`，记录全量 CLI 并发测试中 host command runner 和 proxy serve 端口竞态的排障规则。
- 验证通过：失败套件 focused 复跑 147 个测试通过；`swift test --package-path CLI` 全量 612 个测试通过；根包 `swift test` 224 个测试通过；`git diff --check` 与 `docs-linhay/scripts/check-docs.sh` 通过。
