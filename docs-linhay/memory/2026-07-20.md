## GitHub Issue #146：Simulator 录屏不能只信 container duration

- `triton sim record --duration 3` 可等待约三秒并由 `simctl` 正常退出，但 artifact 仍可能只有一帧、可播放时长约 `0.066667s`；host command 退出码不是视频证据有效性的充分条件。
- AVFoundation 的 `AVAsset.duration` 与 `AVAssetTrack.timeRange.duration` 会反映被拉长的 timeline，本例均约三秒，仍会掩盖一帧 artifact。录屏验收必须使用 `AVSampleCursor` 遍历 encoded samples，以首尾 PTS + sample duration 计算实际时长。
- 成功契约新增 requested/actual/minimum/container/track duration、file bytes 与 `durationValidation=passed`；actual 低于 requested 的 75% 返回 `sim_record_truncated`，媒体 sample 不可读取返回 `sim_record_invalid_artifact`。
- 真实 smoke 证明旧路径的假成功已被改为单个失败 JSON 和非零退出码；`ffprobe` 仅作为 artifact 独立核对，不作为 Triton 产品入口。
- #146 的正式本地门禁、docs 与 public skill package 校验通过。扩展 CLI suite 仍有既存的 `device proxy/alias/bridge` schema 与暂停 `testrec` 断言，不属于录屏切片；本次新增 schema failure 已全部清零。

## GitHub Issue #148：Xcode simulator selector 必须驱动 destination

- `ResolvedXcodeInvocation.simulatorUDID` 正确不代表 `xcodebuild` 使用了同一 target；workspace 保存的旧 destination 若先于显式 `--simulator` 解析，会造成 summary 与 source command 身份分裂。
- destination 优先级固定为显式 `--destination` > real-device selector > 显式 `--simulator` > workspace default destination；只有继承默认 simulator 且没有显式 selector 时，才保留 workspace destination。
- simulator selector 不能一律写入 `id=`：UUID 与 `sim:<UUID>` 使用 `id=<UUID>`，人类可读设备名使用 `name=<name>`。`xcode use` 和 settings/build/test/run 必须共用同一合成函数。
- 聚焦 Xcode 命令测试按 BDD/TDD 从缺少 helper 的编译红灯转绿，10 个测试覆盖旧 destination 覆盖、UUID、前缀、名称与显式 destination 优先级。
