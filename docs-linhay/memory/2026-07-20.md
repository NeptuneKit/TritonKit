## GitHub Issue #146：Simulator 录屏不能只信 container duration

- `triton sim record --duration 3` 可等待约三秒并由 `simctl` 正常退出，但 artifact 仍可能只有一帧、可播放时长约 `0.066667s`；host command 退出码不是视频证据有效性的充分条件。
- AVFoundation 的 `AVAsset.duration` 与 `AVAssetTrack.timeRange.duration` 会反映被拉长的 timeline，本例均约三秒，仍会掩盖一帧 artifact。录屏验收必须使用 `AVSampleCursor` 遍历 encoded samples，以首尾 PTS + sample duration 计算实际时长。
- 成功契约新增 requested/actual/minimum/container/track duration、file bytes 与 `durationValidation=passed`；actual 低于 requested 的 75% 返回 `sim_record_truncated`，媒体 sample 不可读取返回 `sim_record_invalid_artifact`。
- 真实 smoke 证明旧路径的假成功已被改为单个失败 JSON 和非零退出码；`ffprobe` 仅作为 artifact 独立核对，不作为 Triton 产品入口。
- #146 的正式本地门禁、docs 与 public skill package 校验通过。扩展 CLI suite 仍有既存的 `device proxy/alias/bridge` schema 与暂停 `testrec` 断言，不属于录屏切片；本次新增 schema failure 已全部清零。

## GitHub Issue #148：Xcode simulator selector 必须驱动 destination

- `ResolvedXcodeInvocation.simulatorUDID` 正确不代表 `xcodebuild` 使用了同一 target；workspace 保存的旧 destination 若先于显式 `--simulator` 解析，会造成 summary 与 source command 身份分裂。
- destination 优先级固定为显式 `--destination` > real-device selector > 显式 `--simulator` > workspace default destination；只有继承默认 simulator 且没有显式 selector 时，才保留 workspace destination。
- simulator selector 不能一律写入 `id=`：UUID 与 `sim:<UUID>` 使用 `id=<UUID>`，人类可读设备名使用 `name=<name>`。`xcode use` 和 settings/build/test/run 必须共用同一合成函数。
- 聚焦 Xcode 命令测试按 BDD/TDD 从缺少 helper 的编译红灯转绿，10 个测试覆盖旧 destination 覆盖、UUID、前缀、名称与显式 destination 优先级。

## GitHub Issue #151：Evidence partial capture 必须是单一失败契约

- 聚合型 CLI 不能调用会自行打印 JSON 并抛 `ExitCode` 的叶子 resolver；evidence artifact 采集改用静默 target resolver，只在最终 entrypoint 输出一次 manifest。
- `TKEvidenceManifest` 新增向后兼容的 `partial` 与顶层 `error`，`TKEvidenceSkippedArtifact` 新增可选结构化 `error`。旧 manifest 未含 `partial` 时按 `skipped` 是否为空推导。
- 预期 unsupported artifact 仍是 `ok:true, partial:true`；请求或写入失败是 `ok:false, partial:true`、`error.code=evidence_capture_partial`，打印 manifest 后以非零退出。agent 不得因 status/list/version 等局部 artifact 已存在就宣称证据完整。
- 断线测试模拟 list 成功后五个 runtime artifact 全部返回 `target_not_found`，单次 JSON 解码成功，stdout/persisted manifest 一致，且每个 `skipped[].error` 保留原始稳定错误码。

## GitHub Issue #147：Harmony wait 的 transfer timeout 必须服从总 deadline

- host-side poll 的总 timeout 不能只包住循环；其内部 dump/recv 子进程也必须使用剩余预算。Harmony 每次 layout capture 上限固定为 `min(5s, remaining wait budget)`，dump 与 recv 再共享同一个绝对截止时间。
- `hdc file recv` 的瞬时 timeout 是可重试观察失败，不应立即映射为泛化 `request_failed`。`HostHarmonyWaitOutput` 通过 `transientFailureCount`、`lastTransientError` 与 `sourceCommands` 保留错误码、remote path、底层命令及日志路径；持续失败最终返回标准 `timedOut=true` envelope。
- `--gone` 不能把“本轮布局没采到”解释成“文本已消失”；只有成功解析 layout 后才能作 absence 判断。
- CLI wait 与 smoke wait 原先存在两套循环，本轮收敛为共享 helper，避免 timeout、diagnostics 与 condition 语义继续漂移。
- Triton-first 事实显示本机唯一 DevEco emulator 为 Offline，因此仅完成可重复的 Harmony host smoke，没有绕过 Triton 运行裸 HDC 或宣称真实 emulator 验收。

## GitHub Issue #149：iOS Simulator wait 与 host AX 事实源对齐

- 同一命令含 embedded 与 host mode 时，schema 的 `requiresServer` 不能按 embedded 路径一刀切为 true；只要 `--platform ios|android|harmony` 可离线执行，command-level 契约就应标为 false，再由 runtimeScope 和 mode-specific error 表达 embedded 依赖。
- `wait --platform ios` 必须复用 `observeIOSHostAX`，使 `observe tree -> wait -> host input fallback` 读取同一 host-layout 事实源；不能在 CLI help 接受 iOS 后仍把 selector 交给 embedded `/targets`。
- iOS host wait 首期严格限定 ready Simulator 与 text/exists/gone，真机、idle、hierarchy-change、predicate 不隐式降级。`--gone` 只在成功取得 AX 树后判定 absence。
- `host.ios-wait` 直接携带 resolved `HostDeviceTarget`、optional role、matched node、poll/elapsed/timeout 和 sourceCommands；capability 使用独立 `ios-simulator-host-wait`，确保 server/runtime disconnected 时仍可发现并执行。
- 真实 booted iOS 26.5 Simulator 在 server 关闭时完成 match、timeout、gone 三条 smoke，证明修复不依赖 embedded runtime。

## GitHub Issue #150：Xcode discovery 返回的 Package.swift 必须可执行

- `xcode discover` 把 `Package.swift` 作为推荐 container 返回后，`xcode use/schemes/settings/build/test/run` 必须能用 `--package` 直接消费；否则 discovery 只是不可执行提示，会迫使 agent 回退裸 `xcodebuild`。
- Xcode 对 standalone Swift package 没有 `-packagePath` 参数；正确 host 适配是让 `xcodebuild` 从 package 目录启动。因此 `TKHostCommand` 新增可审计 `workingDirectory`，短命与 JSONL streaming 两套 process runner 必须共用同一配置函数。
- 只修通用 host runner 不够：真实 smoke 证明 `schemes` 已识别临时 package，而 streaming `build` 仍会误用调用 worktree。新增 cwd runner 测试后，standalone package 的 generic iOS Simulator 构建同时产出 arm64/x86_64 并返回 `ok=true`。
- repo-local Xcode defaults 增加互斥 `package` container；显式 workspace/project/package 会整体覆盖旧 container defaults，避免显式 package 与历史 project default 被拼成假冲突。
- `schema --command xcode.build --json` 与既有 `xcode build` 形式统一收窄父 schema，build contract 暴露 `--package` 与 `package` summary 字段。

## GitHub Issue #152：真机 launch env 必须使用 devicectl 显式 JSON

- host source command 中出现 `DEVICECTL_CHILD_KEY=<redacted>` 只证明 caller environment 被设置，不证明 CoreDevice 会把原始 key 注入 App；iOS 26.5.2 真实回归已证明该路径可静默失效。
- 当前 `devicectl device process launch` 提供 `--environment-variables <JSON dictionary>`，且明确其优先于 `DEVICECTL_CHILD_*`。Triton 真机 launch 改用该显式 flag，Simulator 继续使用 `SIMCTL_CHILD_*`。
- secret 不只会出现在 process environment，也可能进入 argv。`TKHostCommand` 因此新增 argv index 脱敏集合；实际执行保留 JSON，`sourceCommand` 仅保留 flag 并把整个 JSON 参数显示为 `<redacted>`。
- connected 真机取证必须区分 target readiness 与 App 内动态断言。本机没有可读 `ProcessInfo.environment` 的 Triton/Demo/Bench sentinel App，因此完成 non-mutating target/schema/command contract 验证，不以启动无关 App 冒充端到端成功。
