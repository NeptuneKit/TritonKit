## GitHub Issue #159：UIKit modal tap boundary

- UIKit embedded runtime 的 coordinate fallback 不能只检查命中 view 的 cell ancestor；当 responder chain 属于已呈现 `UIAlertController` 时，必须先终止后续 text/control/cell/gesture resolution，避免相同坐标激活 modal 背后的内容。
- alert action 只使用公开 `accessibilityActivate()`：成功与不支持分别通过稳定 strategy `alert-action-accessibility-activate`、`alert-action-unsupported` 暴露，agent 仍需验证 dismiss 或业务后置状态。
- iOS Simulator fixture 应把 selectable collection 放在 alert 后方，同时覆盖已映射、不可激活和无法映射的 alert subtree view；三类断言都必须包含背景 selection 未变化。
- #159 已由 `01d88c4b` 合并到 `main`，GitHub CI `29910680723` 全部通过后关闭。

## GitHub Issue #160：Xcode one-off build settings

- `triton xcode settings/build/test/run` 的临时 build setting 使用可重复 `--build-setting KEY=VALUE` 表达；key 在 host command 前按 `[A-Za-z_][A-Za-z0-9_]*` 验证，value（包括空值、空格和 `$(inherited)`）保持原样。
- 共享 Xcode builder 必须逐项追加 setting argv，不能用 shell 字符串拼接；机器可读 schema 同时暴露 `KEY=VALUE[]`、适用 subcommand 与 `validation_failed`，parent failure codes 也必须覆盖子命令。
- fake `xcodebuild` smoke 应同时校验 argv 边界、可审计 `sourceCommand`，以及非法 setting 不启动 host command。
- #160 已由 `cb3e61d8` 合并到 `main`，GitHub CI `29912995906` 全部通过后关闭。

## GitHub Issue #161：Embedded screenshot PNG contract

- embedded UIKit screenshot 的 wire metadata 与 bytes 必须同源；当前统一使用 PNG，CLI 不能再把 JPEG payload 写入 `.png` 路径。
- artifact 发布边界同时校验扩展名、runtime metadata 与 magic bytes，不一致统一返回 `artifact_write_failed` 且不写文件；该规则应复用于 screenshot、evidence、replay、test-run、HTTP 与 Web bridge。
- host-side Simulator screenshot 保持独立 PNG 契约；遇到旧 embedded runtime 返回 JPEG 时，升级 runtime 是恢复路径，不允许用错误扩展名掩盖格式。
- #161 已由 `0db4120b` 合并到 `main`，GitHub CI `29924383924` 全部通过后关闭。

## GitHub Issue #162：iOS real-device launch resolution

- platform-less `ios-real:*` / `triton:ios-real:*` selector 必须触发 real-device live discovery，使 install/info/launch 共享同一 selector identity 与 readiness transition；不能在进入 `devicectl` 前误报 `target_not_found`。
- host action 必须读取 `devicectl --json-output`：CoreDevice 1011 / unable-to-locate-device 稳定映射为 `target_offline`，并返回 `device wait-ready` 的结构化 `prepare-target` next action。
- raw CoreDevice identity 只进入 host argv，公开 target、日志与证据继续使用 stable selector；真实设备不可用时只声明不可用分支的 live smoke，不夸大为真实 App 启动成功。
- #162 已由 `f263c399` 合并到 `main`，GitHub CI `29927019645` 全部通过后关闭。

## GitHub Issue #163：Xcode 26.6 xcresult compatibility

- Xcode 26.6 的 test-results summary 会把 `devicesAndConfigurations` / `testFailures` 从历史 singleton 改为 array；兼容层应使用受类型约束的 single-or-array decoder，保持 Triton 已发布的单值 summary DTO，不用宽泛 `Any` 吞掉无效结构。
- Xcode 26.6 tests tree 可能不再包含 `Test Case Run`，而是让 failed `Test Case` 直接持有 `Failure Message`；parser 需兼容 nested 与 flattened 两类树，并在存在 run child 时避免重复记录。
- result parser 兼容工作必须同时使用 compact 脱敏 fixture 与本机真实 `.xcresult` smoke；公开 issue 只保留 shape、计数、错误码和结构化摘要，不上传原始 bundle。
- #163 已由 `938f9640` 合并到 `main`，GitHub CI `29929843919` 全部通过后关闭。

## GitHub Issue #164：Evidence Simulator screenshot fidelity

- iOS Simulator evidence 的视觉事实必须优先来自 host-composited framebuffer；embedded runtime screenshot 只能代表 App layer，不能用于证明 system sheet、键盘等系统合成层的视觉完整性。
- evidence artifact 通过 `scope`、`source`、`fidelity` 与 `visualAcceptance` 区分 host 主截图和 runtime 辅助截图；runtime 辅助图使用独立 `screenshot.runtime` kind 与路径，避免下游误取。
- host screenshot 失败时保留 runtime 诊断价值，但整体必须返回 `failed-partial`、`host_screenshot_unavailable` 与可执行 `triton sim screenshot` 恢复动作，不能降级成伪完整成功。

## GitHub Issue #165：Xcode schemes discovery timeout

- Xcode container discovery 的默认深度必须覆盖常见 nested app / monorepo 布局，同时保持生成目录排除；当前默认统一为八层，并继续允许 `--max-depth` 显式覆盖。
- `xcode schemes` 与 build/test/run 使用不同 timeout 契约：只读 scheme listing 通过 `--timeout-seconds` 控制，默认 300 秒；缓存 package state 足够时可用 `--disable-automatic-package-resolution` 避免自动 Swift package 更新。
