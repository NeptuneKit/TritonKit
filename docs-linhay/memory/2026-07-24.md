- #168 当前 real-device terminate 直接将 bundle ID 传给 `devicectl device process terminate`，而 Xcode 26.6 help 要求 `--pid`。官方本地 CoreDevice 模型审计没有证明 `bundleIdentifier -> App executable -> running-process executable -> PID` 的一一关系：`AppInfo` 有 bundleIdentifier 与可选 URL 但没有 executable；`ProcessInformation` 有可选 executable URL 与 processIdentifier 但没有 bundleIdentifier；没有官方 join/路径正常化规则。`device info apps` 与 `device info processes` 的 help 也没有提供可表达该链的字段关系。
- 可定位证据：`/Library/Developer/PrivateFrameworks/CoreDevice.framework/Versions/A/Frameworks/CoreDeviceClientJSONSupport.framework/Versions/A/CoreDeviceClientJSONSupport` 的本地 Swift 符号；CoreDevice `devicectl` binary `/Library/Developer/PrivateFrameworks/CoreDevice.framework/Versions/A/Resources/bin/devicectl` 的 `strings -a -t x` 偏移 `0x128150`（`Processes.swift`）、`0x128220`（running processes 命令）、`0x12d1f0`（versioned/stable JSON file interface）；以及 `xcrun devicectl device info apps/processes --help`。结论是 **no evidence**，不实现 `info processes` parser/resolver，不用 URL、basename、path、进程名或宿主 `ps` 猜 PID。
- 已保存 Triton-first status/doctor/capabilities/plan：server `127.0.0.1:19421` 不可达，runtime/real device 未连接；后续使用 fake/devicectl adapter tests，真实设备 smoke 如不可用只记 blocker。
- 控制流为 `HostAppTerminate.run -> planHostAppTerminate -> TKDevicectlCommand.terminateApp`；因此采用安全 fallback：shared `terminateApp` 只接受明确 PID 并生成 `--pid <pid>`；iOS real plan 在 builder 前抛出稳定 `app_terminate_pid_resolution_unavailable`，不调用 `info processes`、不产生 terminate command；Simulator/Android/Harmony 继续使用既有 builder。
