## SP-169 / GitHub #206

- issue 事实：agent 需要核对已安装 iOS Simulator App 是否符合预期发布版本；`triton app info` / `triton app list` 只暴露 `CFBundleVersion`（build number，字段名 `version`），没有独立的 marketing version（`CFBundleShortVersionString`），调用方被迫另读 `Info.plist`。
- 裁决：`TKHostInstalledApp` 新增 `marketingVersion`（`CFBundleShortVersionString`）与 `buildNumber`（`CFBundleVersion`）两个无歧义字段；legacy `version` 保留，iOS 上明确映射到 build number（与 `buildNumber` 相同），代码注释、schema description、`outputSemantics` 与文档统一标注 deprecated 指引。
- 顺带修复 schema 缺口：`hostAppInfoOutputContract()`（selector `host.app-info`）此前已定义但从未挂到 `app` schema 的 `outputContracts`；本轮挂载并新增 `hostAppListOutputContract()`（selector `host.app-list`），`list`/`info` subcommand 的 `outputSelectors` 覆盖这两个 selector。
- 共享模型边界：`TKHostInstalledApp` 同时被 iOS 与 Android parser 使用；Android 侧未改解析，`buildNumber` 自然落出为当前 parser 写入的 `CFBundleVersion`（即 `versionName`），`marketingVersion` 为 nil，`versionCode` 解析不纳入本轮。
