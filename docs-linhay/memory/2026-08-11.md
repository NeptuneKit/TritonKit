## SP-168 / GitHub #205 目标租约（target lease）

- issue 事实：多个自动化 agent 并行跑 iOS Simulator smoke 流程时没有可见预留状态；后到者会在首个流程活动时改变前台页面（`app open-url`、`act tap` 等），产出误导性流程证据。
- 裁决：租约是 `triton serve` 进程内的共享状态（每目标最多一个、带界 TTL、不透明 owner 标签、`readonlyObservationAllowed` 策略字段）。CLI 面为 `triton target lease acquire|status|release|takeover`；mutating 命令 `app open-url|launch|terminate` 与 `act tap` 接受可选 `--lease <token>`，由 `POST /v1/target-leases/check` 原子判定。冲突统一返回 HTTP 409 `{ ok:false, surface:"target-lease", error:{ code:"target_lease_conflict", leaseReason: held_by_other|lease_expired|lease_not_held|lease_release_denied|lease_takeover_required, currentOwner, currentLeaseID, currentExpiresAt?, suggestedCommands } }`。未传 `--lease` 时完全不查询租约（opt-in，0.2.18 行为不变）；只读观察命令（`observe`/`wait`/`app list|info`/`sim screenshot`/`target lease status`）从不检查租约（豁免）。
- 契约细节：TTL 默认 300s、范围 30…86400（`lease_ttl_out_of_range`）；acquire 同 owner 幂等 `already_held`，过期自动替换；release 需匹配 token（`lease_release_denied`），无租约为幂等 no-op；takeover 显式 `--confirm` 才接管（`lease_takeover_required`），返回 `previousOwner`；`check` 对无租约/过期/他人持有均 fail-closed。目标 key 用 `TKNormalizeTargetLeaseKey` 剥离 `sim:`/`host:ios:`/`triton:ios-simulator:` 前缀与 `/app:<bundle-id>` 后缀，acquire 时尽量把 `booted`/`current` 解析为具体 UDID。
- TDD red：新增 4 个 focused suites（`TargetLeaseStoreTests`、`TargetLeaseHTTPTests`、`TargetLeaseCommandTests`、`TKTargetLeaseModelsTests`）首次因租约类型/命令/路由缺失而编译失败；最小实现后转绿（纯状态机、Hummingbird `.router` 内存路由、parser/schema/conflict-envelope fixtures）。`public-skill-command-schema.json` 的 `target` 快照同步为 `["lease"]`。
- 兼容性：`TKCLIErrorDetail` 新增 4 个可选字段（`leaseReason/currentOwner/currentLeaseID/currentExpiresAt`），旧 JSON 仍可解码；`app launch/terminate` 新增可选 `--host`/`--port` 以触达租约服务（纯增量，不破坏既有接口）。
