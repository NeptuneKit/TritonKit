## SP-164 / GitHub #201 Harmony `act find` host adapter

- issue 事实：`act find` 缺 `--platform`/`--hdc` 选项；即使 `--device` 指定已连接的 Harmony target，也会尝试 embedded iOS runtime server 并返回指向 `http://127.0.0.1:19421/targets` 的 `server_unavailable`，而 `act.find` schema 又广告 `runtimeScope: embedded|host-ios|host-android|host-harmony`，host-Harmony 实际不可达。
- 裁决：不修改 iOS/Android embedded 路径；给 `act find` 加 `--platform`/`--adb`/`--hdc`，在 `resolveRuntimeClient` 前用 `actFindHostRoute` 分流——`--platform harmony` 走 host-harmony（`resolveHarmonyTarget` + `dumpHarmonyLayout` + `TKHarmonyLayoutParser.nodeSummaries` 精确匹配，产出与 embedded 相同的 `TapTargetResolution`/`target.resolution` 契约），`--platform ios|android` 返回 typed `unsupported_capability`（hint 指向 `observe tree`/`act tap`），无 `--platform` 保持 embedded。
- `resolveHostHarmonyFind` 为纯函数：候选按 depth/y/x 稳定排序，`--within`/`--at` 过滤、`--index` 选择、`--all` 暴露 candidates；无匹配与 index 越界均复用 `TKTapTargetResolutionFailure` → `text_not_found`，与 embedded find 对齐。
- schema：`act.find` optionalOptions 增补 `--platform`/`--adb`/`--hdc`，failureCodes 增补 `unsupported_capability`/`target_offline`/`host_command_failed`/`harmony_layout_path_not_found`，usage/examples 含 `--platform harmony --device <harmony-target>`；`--platform` option description 说明 find 仅实现 harmony、ios|android 返回 unsupported。
- TDD red：`HarmonyActFindTests` 先因 `Find` 无 `--platform` 选项与 `actFindHostRoute`/`resolveHostHarmonyFind` 缺失而编译失败；最小实现后 focused suite 全绿（parser/routing/纯函数解析/错误契约/schema contract 与 schema-backed argv 校验）。
