## TritonKit × Pinky 机制差距审计

固定 Pinky 最新恢复副本 `329f35ac2e240805e265a483fa2d3ff0f84780d3` / `v2026.1111.17`，相对历史pin增加324 commits；Triton实读 main `14574a7b` + 当前WIP。报告：[差距矩阵](../spaces/SP-279-pinky-reference/plans/20261111-tritonkit-pinky-gap-audit.md)，证据hash：[gap evidence](../spaces/SP-279-pinky-reference/plans/20261111-pinky-gap-evidence.json)。未运行Pinky、依赖、设备或性能。

结论：Pinky领先的是常驻gateway、人工approval/TakeOver/HandBack/Stop/resume、真实手机后台display、任务历史/录屏与Agent一键接入；Triton已有resident iOS跨进程lock/session ledger/requestID fingerprint去重、Android Accessibility Bridge、node alias freshness、workspace execute→settle→observe→business assert和可执行`.tritonplan`，差距是这些机制未统一成跨入口人工协同owner。Pinky Watch replay是截图/步骤回看，不是动作重执行；其录屏导出另行审批且不遮OTP/blocked通知。Pinky自身也不是OS sandbox，sessionless兼容按User-Agent不能作为强身份。

本轮发现并以零provider parser探针复现G0：HTTP parity会给typed device action追加`--json`，但DeviceActionCommonOptions/parser未声明该参数，完整release CLI返回`unknown_option`；HTTP生产请求未启动，产品代码未修。新经验：外部对照必须区分局部已有机制和跨owner贯通，不能按字段/命令名判定完成；HTTP mock executor绿色不证明真实argv parser可用；recording/evidence/report存在不证明媒体完整；停止、重连、settle、replay名称各自保留语义。
