## 采用边界

上游查询仍为只读；重点追踪 live ref/alias 新鲜度、采集预算、视觉稳定/OCR、UI 健康/熔断、agent schema/错误反馈，以及 Runner/DDI/签名兼容和安全修复。2026-10-16 用户追加“后期评估可以纳入的改动可以直接按照这个流程直接进入开发”，替代此前“后续采用需逐项授权、不自动实现/本地提交”的限制。当前有效授权如下：

1. 先完成上游增量读取，再对照当前源码、测试、既有交付与产品边界评估；保存采用/已覆盖/观察/拒绝及理由、BDD和文件面。不得把上游声明或旧差距直接当当前缺失。
2. 评估为可纳入且属于现有产品范围的切片，直接建立独立实现 space、branch/worktree 和执行会话，开发与验证无需逐项重新确认；紧耦合改动合并切片，互不冲突的文件面再并行。
3. 同步建立或复用适合该批次的主控会话，允许其协调本批次执行会话、核对真实候选、修复冲突、重跑联合门禁，并完成必要的本地提交和本地 main 合并。验证失败继续修复；证据不完整不能标合并完成。
4. [统一采用登记](../SP-207-reference-adoption-pipeline/plans/adoption-state.json)与上游读取检查点分别维护：按来源/机制/现有实现去重；已登记任务持续跟进，不因新 SHA 或重试再次创建同一任务。仅在会话创建成功后记录真实 thread ID；失败记为待重试，不冒充已分派。读取检查点推进不代表开发完成。
5. 运行上游代码、安装/升级依赖、签名、挂载 DDI、设备动作、扩大远端/AWDL/云等产品边界，以及 push/tag/release 不随此授权自动开放；确有必要时在独立切片说明具体需求。产品与真实验证范围遵守 AGENTS，保留其他任务 WIP，不 stash、不整包混入。
6. 有新采用批次、重要结果/阻塞时简要中文通知；上游无变化且无待推进的采用任务时保持安静。日常执行不另建重复自动任务，保持每天北京时间10:00计划。
