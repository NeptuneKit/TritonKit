## Requested / Observed

落实 SP-202 验收第 1、2 行：serve 广播显式 opt-in、真实发布生命周期、SDK 默认不自动发现首个服务、显式 host 优先、候选消歧、Debug/Release 分别验证。未增加认证、远端产品、Web 写控制面、外部依赖或 Runner 改动。

- `serve` 默认与显式 LAN bind 都不创建 Bonjour 发布。`--advertise` / `TRITON_ADVERTISE=true|1` 开启，`--no-advertise` 覆盖环境，`false|0` 关闭；非法环境值和 port/host 在监听前拒绝。
- HTTP bind 成功才启动发布；专用 Foundation RunLoop 保证回调可被异步 CLI 接收。wanted/publishing 表示意图与流程已发起；advertising 只由 `didPublish` 确认；failed 来自 `didNotPublish`；已发布服务的 stopped 需 `didStop`。失败不会被清理回调抹掉；重试建立新 service，旧回调不能覆盖新状态。没有伪造 NetService 超时回调。
- `/status` 与 `triton status --json` 包含 optional `discovery`，旧 HTTP/CLI 响应仍可解码。`identityVerified=false`，发布记录不证明 LAN 可达或服务身份。
- SDK `.environment()` 默认不浏览，保留显式环境/bundle host 优先。可用 `.environment(discoveryPolicy: .bonjour(timeout: 0.15))` 或 App 进程 `TRITON_DISCOVERY=bonjour` 显式开启；超时 `TRITON_DISCOVERY_TIMEOUT_SECONDS` 必须有限且 `0<t<=5`。
- 完整有界窗口只接受唯一已解析候选。多候选（包括未解析或移除的竞争服务）、搜索失败、非法配置、无候选均拒绝，不静默回退 loopback。`.bonjourDiscovery(timeout:)` 提供原因和候选；公开 TXT ID 只作未认证 metadata，不参与信任/消歧。`.bonjour(timeout:)` 保留可空 endpoint 兼容入口。
- Release 默认参数、显式发现和 start/connect 均保持 no-op；未因返回候选或 TCP ready 声称认证。

## Fixes made / 经验与 memory 移交

1. 默认参数也可能产生网络副作用：Release 保护必须在 resolver/browser 构造之前，不可只保护 start 函数体。已写回 [Debug-only runtime 权威文档](../../../dev/20260519-debug-only-pm-runtime.md)。
2. 发现窗口内被移除的候选不能被迟到失败/成功回调复活；公开 ID 和单候选不能升级身份。已写回 [iOS 接入指南](../../../dev/20260519-ios-integration-guide.md) 与公开接入 skills，新增时序回归。
3. Release 三个既有测试错误地按 Debug 功能专属响应解码。实际 handler 返回 `TKErrorPayload`、`.ping`、disabled message；本轮只修正拥有的测试文件，未改 handler。权威 Debug-only 文档已记录两条分支的不同断言。
4. 新 SDK suite 曾与已有 suite 同时操作 singleton；已将 start/连接测试移入既有 serialized suite extension。独立 `.serialized` suite 不会彼此互斥；沿用既有治理原则，不新增重复 AGENTS/skill。

5. 最终解码审计发现 synthesized Codable 会接受远端伪造 `identityVerified:true` 并让 CLI 原样输出；先补负例复现 2 issues，再用显式 decoder 把该字段固定 false。已写回 CLI 契约/iOS 接入说明；服务自报不能创造认证。
