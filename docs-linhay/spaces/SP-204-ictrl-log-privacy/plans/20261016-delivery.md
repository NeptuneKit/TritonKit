## 最小日志契约

响应入口每个可见事件一行，最多 512 UTF-8 字节（包含 stderr 写入的换行）。日志字段固定：`type`、`id`、`frameBytes`、`payloadBytes`、`outcome`、`received`、`failures`、`healthyPings`。

- `type` 来自已解码的 `TKRequestType` 封闭枚举；无法解码时固定 `unknown`，ID 固定 `none`。不打印未知 type、字典键或任意字符串。
- ID 是协议整数；字节数和计数是本地计算值；`outcome` 是 helper 内部固定分类。app/device/bundle/SDK、层级 title/class、error code/message/hint、token 和任意嵌套内容均不进入格式化器。
- 对 `ok:false`、非 null error、非空 errors、legacy `TKErrorPayload`，记录 `remote_failure`；未知 message、无效 payload/ping、异常 UI health、registration 拒绝分别有固定分类并增加失败计数。无法判断业务结果的合法 payload 标 `received`，不伪造成功。
- 对 ping 使用真实 `TKRuntimePingResponse` 解码，`pong:true` 且 UI health 缺省（旧协议）或 ready/允许请求才聚合。首次成功及每 100 次成功输出一次；其它可见日志携带当前累计计数。busy/timed_out/circuit_open、pong false、畸形 ping 均不抑制。
- id=0 ping 沿用原有直接返回行为，零日志、不缓存，也不纳入新计数。这是既有行为保护，不是新增降噪能力。
- 计数由锁保护，饱和递增，默认 logger 为进程累计，恒定存储；不是上游的 500 行环形缓冲，也不新增状态接口或关机 flush。静默尾段计数在后续可见事件/百次成功汇总中呈现，进程退出后不持久化。
- serve 当前没有 verbose 配置。本 helper 没有原文开关，任何其它命令的 verbose 也不会打开此入口。没有新配置或环境变量，因此无配置迁移。
- 原始业务 payload、response cache、hierarchy cache、App metadata 和 registration 决策保持原行为。原本不能解析/无 payload 的消息仍不缓存。`store` 参数保留调用签名兼容，不改其他会话负责的 CLIServeCommand。

## 本地门禁隔离

`verify.sh --local` 原脚本包含固定 `/tmp/triton-verify-*` 文件，与并行会话有共享写入风险。本轮在 `.build/sp204-validation/verify-local-isolated.sh` 生成原脚本副本，仅将计算 repo root 的一行固定为本 worktree、将这些 `/tmp` 前缀替换到本 worktree 的 `.build/sp204-validation/smoke/`；其余检查步骤、命令与断言保持不变，仓库脚本没有修改。因此记录为**本地门禁的隔离等价执行**，不冒充原脚本逐字执行。

执行：

```sh
TRITON_VERIFY_XCODE=0 TRITON_IOS_RUNTIME_SMOKE_PORT=29404 \
TMPDIR="$PWD/.build/sp204-validation/tmp" \
bash .build/sp204-validation/verify-local-isolated.sh --local
```

Release binary 来自本 worktree `.build/cli/release/triton`。Harmony 使用 fake hdc；iOS observe smoke 使用自己的 loopback fixture HTTP 服务，脚本退出时清理本进程。退出后检查无 LISTEN 进程、连接拒绝（errno 61）、启用 SO_REUSEADDR 可重新绑定，确认没有残留监听器；最初不启用复用的 bind 返回 EADDRINUSE，不能仅凭该结果推断服务泄漏。`TRITON_VERIFY_XCODE=0` 明确跳过可选 Simulator build；没有操作外部设备、签名、DDI、iCTRL、SDK bootstrap 或 Runner。
