补充一个匿名只读诊断工作台的消费证据，适用范围为“已有运行快照 + 独立读取状态”，不要求所有列表引入缓存，也不建议增加 API。

- **产品约束**：浏览器只观察 DTO，实际执行仍由独立 CLI/HTTP 负责。数据读取失败与任务本身 failed/paused 是两个维度；保留旧 DTO 时仍显示旧运行状态，另以 Notice 明示“读取失败，以下保留上次读取记录”。不能将恢复显示当作任务成功。
- **实际制品与组合**：npm `@linhey/rhine-design@0.11.3`，React 19 + Vite 7 + Node 24；使用 Surface、KeyValue、Tabs、Badge、Notice、Skeleton、EmptyState、DataTable、CopyButton。无新组件或私有样式覆盖。命令区仅复制，并依据真实复制 Promise 显示结果；评审环境显式注入合成复制反馈，不访问业务剪贴板。
- **已验证事实**：Node 渲染回归覆盖缺少快照、加载、读取失败、旧快照留存、空路径/空命令、未知覆盖率和长身份文本；浏览器三主题 × 400/520/880 画布 × 100/200% CSS zoom × 六种合成状态共 108 组，无页面横向溢出。路径表格在局部容器滚动，不裁掉列；方向键切换 Tabs 并保持可见焦点。主题/尺寸变化保留页签实例。
- **通用建议**：在本 issue 的异步数据组合配方中补一个只读诊断例子，分别表达“任务状态”“读取状态”“内容是否旧快照”，并说明复制操作不等于执行。业务时间缺失时不合成 freshness 时间。
- **可观察验收**：旧 paused/failed 记录遇到读取错误仍可读且明示旧数据；没有快照时加载和错误不显示成功空态；命令复制失败不显示已复制；空路径与 unknown coverage 不等于健康/全覆盖。
- **限制与阶段**：本轮为消费端组件/合成场景验证；没有重新验证真实后端、原生设备、屏幕阅读器或浏览器原生 zoom。建议已反馈，是否吸收规范与发布仍由上游决定。
