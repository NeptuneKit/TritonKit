补充消费端验证（仍固定 npm `@linhey/rhine-design@0.11.3`，尚未升级）：

- **已验证事实**：产品专用最小语义树与公开 Tabs、Dialog、CopyButton、Select、Notice 组合，保留只读 DTO。三平台分别展示实际来源语义，没有把单源布局树伪装为独立 View/AX 双源；刷新失败保留旧节点并标识失败。
- **已验证事实**：方向键/Home/End、Enter 选择、外部几何画布→树与树→画布选中均通过浏览器验证。常驻树采用扁平 treeitem + aria-level/posinset/setsize，单一 Tab 停靠；焦点移动与选择分离。目标固定后旁边画布切换不改变固定目标，回到跟随后恢复共享目标。
- **已验证事实**：400/520/880 内容宽度、100%/200% CSS zoom、三主题共54组长文本布局没有窗格横向溢出；另实测详情浮层主题归属、Escape 焦点归还、异步复制失败。此证据是浏览器合成场景，不代表原生设备或浏览器原生200%缩放验收。
- **已验证事实**：节点更新动画实际播放时间从约33ms推进到183ms；1秒后清理提示。系统减少动态关闭动画，保留短时静态标记。未宣称全场景 paused；如未来提供 paused 必须同时暂停高亮寿命计时器，不能只暂停 CSS。
- **产品约束/组合经验**：缩放下画布命中应把 client 坐标除以实际 bounding rect，再映射 DTO 坐标，不能混用未缩放的布局宽高。分隔条采用相邻指针位移，避免把总位移反复加到已更新比例。菜单在正常文档流内，避免覆盖只读状态。
- **通用建议，待上游决定**：优先把常驻树与外部画布、固定/跟随目标、刷新保留快照、更新高亮的组合验收写入规范/展台；无需预设新增通用 Tree API。消费端仍保留受限适配，待固定可消费制品覆盖并验证等价行为后移除。
